# 丰淮商贸采购下单助手

> **MVP v1.0（2026-08-05 定稿，最终功能范围）**：微信小程序全员使用（4角色），微信云开发后端，蓝牙打印，无 Web 后台。**MVP 为最终功能范围，无二期增强**；催收闭环/审计日志/趋势报表/微信支付后续作为独立升级模块按需追加（机制见《docs/prd/小程序MVP落地计划与技术架构》§7）。含智能录入（文字/语音快速下单）。

## 项目概述

为丰淮商贸的下单员、分拣员、库管、老板提供一套**超轻量、低成本、即开即用**的小程序下单解决方案，覆盖「智能录入 → 录单 → 分拣 → 出库 → 赊销收款 → 打印/转发销售单（西安迈尚模板）」全流程。支持**文字/语音快速下单**、**全局字号缩放（适老化）**与**0 元订单拦截**。报表中心（导出中心：商品/客户汇总 + 收款台账，CSV导出）为 MVP 已实现范围（见 PRD MVP 13 项第12项）；趋势报表等后续增强为独立升级模块。

- **载体**：微信原生小程序（全员使用，无任何 Web 后台页面）
- **后端**：微信云开发（CloudBase）Serverless，零服务器、零域名、零运维
- **打印**：小程序蓝牙打印（ESC/POS 指令，58mm/80mm 便携热敏）
- **工期**：约 32 人天（MVP 生产化，1 人全栈约 6–7 周 / 2 人并行约 4 周）
- **报价**：开发服务费另计（见《docs/prd/工期与工作量评估》MVP 专项）；甲方平台费首年约 **269 元（个体工商户）** 或 **539 元（公司）**，次年起约 240–540 元/年

## 技术栈

| 层 | 技术 |
|------|------|
| 前端 | 微信原生小程序 + TypeScript + Vant Weapp |
| 后端 | 微信云开发：10 个云函数（29 个接口）+ 11 个数据库集合 + 云存储 |
| 打印 | ESC/POS 指令层 + 微信蓝牙 BLE API（芯烨/佳博/汉印 58mm/80mm） |
| 导出 | 小程序端生成 Excel，微信转发/保存 |

## 核心功能

| 模块 | 说明 |
|------|------|
| 登录/权限 | 微信一键登录，4 角色权限矩阵（RBAC） |
| 录单 | 单栏布局：选客户即**自动带出上次订单的商品与数量**（标「预填」，可改可删）；点「+ 添加商品」选品弹窗默认仅列前 3 个常购、搜索后全列；件+包双轨（单位统一"包"）；**订单内可改价（仅当前订单）**；**客户下单自带上次价格**；1.0 起**取消订单级「收款方式」选择，所有订单默认未付款**（收款渠道"现金/微信"仅在收款登记/确认时选择，用于台账拆分） |
| 订单管理 | 状态流转（**新建即入「待分拣」**，无草稿/保存草稿环节；待分拣→已分拣→已出库→已完成；rejected/cancelled 为遗留态，当前流程不触发）；**当日按客户分组完整卡片 + 昨天及更早折叠单行**；订单卡片内**直接展开商品明细**（名称/规格/数量/小计），无需逐一点开详情；历史订单折叠行展示商品标签；全员可下单/改单/删单；**0 元订单不生成且不计入任何列表；已成订单中"0件+0个"商品行不显示** |
| 分拣工作台（「分拣出库」分拣段） | 待分拣 → 已分拣，一键完成（`startSorting` / 全部分拣）；可填分拣备注；原有「驳回(必填原因) / 暂存配货 / 物流件型弹窗 / 14:00 超时自动确认」已整体移入二期规划（当前 MVP 取消） |
| 库管工作台（「分拣出库」出库段） | 待出库(已分拣) → 已出库，库管一步确认（`confirmOrder` / 全部确认）；可填出库备注 |
| **赊销收款管理** | 独立 Tab「赊销」含三栏：📋客户台账（以客户为单位显示总账 = **应收总额 / 已收 / 未结清**，金额守恒：应收 = 已收 + 未结清）/ 📌未结清 / ✅已结清，外加独立「✅ 收款确认」按钮；收款两步——① 登记收款（`receivable:collect`，下单员/分拣员可、库管不可）；② 确认收款（`receivable:confirm`，库管可、下单员/分拣员不可）；支持一笔订单多次部分收款直至结清；用「已收」(received，含部分收款/折价) 替代原「已结清」；导出报表支持周期选择（全部/今日/本周/本月/自定义），明细行含订单号（含时间故不重复显示时间列），汇总行显示 应收/已收/未结清 |
| **转发客户微信（1.0）** | 新建/已有订单均可一键把**订单明细卡片**转发给客户微信（绿色订单卡片：客户、商品、数量、金额、未付款状态），供客户核对；**不含任何收款码**，与 1.0 取消的收款码卡片是两回事 |
| 打印 | 送货单按客户要求的「西安迈尚食品销售单」模板原样打印：客户信息 + 商品明细表（序号/商品名/数量/单价/金额）+ 合计（大写+小写）+ 累计欠款 + 制单人 + 签收栏；**不额外叠加三方操作人追溯/分拣备注/收款状态/物流件型**（客户指定格式）；商品件+包合并 1 行、无规格列 |
| 销售单模板（西安迈尚） | 统一销售单模板：去 NO.、金额后独立备注列、制单人电话自动取登录人；打印与微信转发共用 |
| 全局字号缩放 | 状态栏「字」按钮 + 「我的」页入口，调节范围 70%–130%，持久化（适老化） |
| 导出中心 | ✅ MVP 已实现：报表统计3视图（商品/客户/收款台账）+ Excel/CSV 导出（入口「我的」→报表统计） |
| 智能录入 | 文字/语音快速下单，支持粘贴微信聊天记录或语音输入，智能解析商品名称、数量、客户信息，模糊匹配库中已有商品和客户，支持智能记忆（上次选择自动复用）；语音转文字对接腾讯云语音识别（录音文件识别 ASR），复杂语义理解接入腾讯云 TokenHub 大模型（NLP，OpenAI 兼容，23 个免费额度模型，默认 hy3），密钥由管理员在「系统设置」配置 |
| 系统设置（仅管理员） | 「我的」页入口：AI 服务配置（腾讯云语音 ASR + TokenHub NLP 分开配置，各自独立密钥）+ 打印机配置（品牌/纸宽）+ 数据备份说明；AI 密钥仅存云端，未配置时智能录入自动降级为纯规则引擎 |
| 操作记录 | 订单详情页底部「操作记录」区块，时间倒序展示订单完整操作历史（创建/编辑/删除/收款/分拣/出库），存 order_logs 集合 |

## 订单状态机

```
新建订单即入：待分拣(SUBMITTED) ──分拣一键「待分拣→已分拣」(startSorting/全部分拣)──→ 已分拣(SORTED) ──库管一步确认「待出库(已分拣)→已出库」(confirmOrder/全部确认)──→ 已出库(CONFIRMED) → 已完成(COMPLETED)

draft(DRAFT)、cancelled(CANCELED)、rejected(REJECTED) 状态保留定义，但当前流程不触发（无草稿创建/无取消入口；驳回为遗留/二期，不纳入主流程）。
```

收款状态（独立维度）：`unpaid` 未收款（默认）→ 登记收款 → `pending` 待确认 → 库管确认 → `paid` 已收款。

订单号规则：`丰淮商贸-YYYYMMDD-NNNN`（如 `丰淮商贸-20260803-0001`）。

## 升级与版本管理（要点）

- **版本号**：全文档与原型共用同一版本（当前 **MVP v1.0**）。MVP 为最终功能范围，无二期增强；新增完整模块 → 次版本（如 v1.1 催收闭环），走"独立升级模块"通道。

- **一致性门禁**：每次改原型必须同步 ERD/API/TDD/PRD/用户手册；发布前按评估报告自检清单核对。

### 使用说明

1. 进入「设置」页面
2. 点击任意主题卡片即可切换
3. 切换后立即生效并保存到本地
4. 重启小程序后保持上次选择的主题

### 技术实现

- 使用 CSS 变量实现动态主题
- 主题配置保存在 `utils/theme-helper.js`
- 导航栏颜色随主题自动调整
- 所有页面统一应用主题样式
