# 钱多多小程序 — 线上事故处置 Runbook

> 适用范围：云函数（CloudBase env `cloud1-d6g75loi673b1e039`）/ 小程序线上 / 数据库。
> 目标：故障 10 分钟内按本册定位到处置动作。配套：全局 INC 流程（P0-P3 分级→根因→复盘写 CHANGELOG + 错误经验库）。

## 0. 分级标准（先定级再动手）

| 级别 | 定义 | 响应时限 | 示例 |
|------|------|---------|------|
| P0 阻断 | 资金/数据错损、核心流程不可用（登录/下单/出库/收款全断） | 立即，30 分钟内给结论 | 云函数全部超时；收款写入错误；订单金额算错 |
| P1 严重 | 核心流程可用但出错，无绕行路径 | 1 小时内定位 | 某状态流转恒 5001；打印模板错乱 |
| P2 一般 | 非核心流程或 UI 细节，有绕行路径 | 当日处置 | 报表导出慢；某弹窗文案错 |
| P3 轻微 | 不影响使用（日志/元数据/文档） | 排期 | 日志噪音；name 残留 |

定级后：P0/P1 立即同步使用方（老板/店长）并在群内通报进展；处置完成后进入 24h 观察期（见 §6）。

## 1. 通用定位三步（任何故障先做）

1. **看日志**（1 分钟）：`tcb fn log <函数名> --env cloud1-d6g75loi673b1e039`，或微信开发者工具 → 云开发 → 云函数 → 日志；找 ERROR 关键字，记下 event.action 与返回 code。
2. **看错误码**（1 分钟）：对照 docs/api/API_接口文档.md §1.4 判断是参数类(1001/4001/4002/5002) / 权限类(2001) / 状态类(3002/4004) / 服务类(5001)。
3. **复现确认**（3 分钟）：开发者工具云函数本地调用，最小 event 复现；**禁止直接在生产数据上试写**，复现写操作一律用 TEST 前缀数据，测完清理。

## 2. 常见故障处置清单

### 2.1 云函数调用超时（callFunction 30s 无返回）
1. 查日志是否有长查询（未命中索引）——热路径查询必须命中索引（索引名在代码注释里）
2. smart.transcribe：ASR 端到端转写 >30s 属已知现象，config.json timeout 已放宽到 60s；先确认没被改小
3. 瞬时性（COS 上传抖动）：单次重试即可；持续超时 → 查 CloudBase 控制台该函数 CPU/内存，必要时调规格
4. **禁止**把 callFunction 等待改成无限大——超时是信号不是噪音

### 2.2 E11000 唯一键冲突 / 双写
1. 查日志里的 index 名，定位是哪张表哪个唯一索引
2. system.setConfig 已知坑：`.set()` 对已存在文档会撞 E11000——正确姿势=先查后写（存在 update / 不存在 add / 竞争兜底 update）；代码若回退成裸 .set() 按此修
3. 业务唯一键（sku 等）冲突返回 1001 是正常校验，不是事故

### 2.3 权限/越权异常（恒 2001 或该拦没拦）
1. 本地跑 `npm run check:perms`，确认 perm-matrix-shared.js 双份一致
2. 查 perm_configs 集合：管理员误关权限键 → 小程序「成员管理 → 权限配置」恢复，或调 users 的 reset-perm
3. member:manage 被误配给非 admin：save-perm 有锁定保护会自动过滤；若发现绕过 → 按 P0 查代码

### 2.4 金额/守恒异常（P0，立即停写）
1. 先冻结：告知使用方暂停收款/出库操作（不删数据）
2. 核对口径：应收 = 已收 + 未结清；逐单对 orders + 收款记录
3. 金额一律整数分/两位小数元；查是否混入浮点 toFixed 写库（已知红线）
4. 数据修复必须留痕：修前导出集合快照，修后逐单复核，写进 CHANGELOG

### 2.5 数据库脏数据（data.data 嵌套 / 字段缺失）
1. 已知根因：@cloudbase/node-sdk 的 doc().set(x) 与 wx-server-sdk 的 {data: x} 口径混用 → 写出 data.data
2. node-sdk 写后必须回读验证顶层 key；发现嵌套用一次性清洗脚本修（脚本入库、幂等、跑前备份）

### 2.6 微信登录/绑定异常
1. need_bind=true 且邀请码失效 → 管理员重新生成邀请码（auth getInviteCode，7 天有效）
2. 首管理员丢失：方案 A 下"无 admin 时第一位登录者自动 admin"，仅无 admin 时触发；已有 admin 时不能裸重置（P0，先备份 users 集合）

## 3. 云函数回滚（Serverless 无服务器级回滚，回滚=重部署上一版）

1. 找回滚目标：`git log --oneline cloudfunctions/<函数>/` 定位故障引入前的 commit
2. `git checkout <commit> -- cloudfunctions/<函数>/`（只取该函数目录）
3. 部署：`bash deploy/scripts/auto-deploy-cloudfunctions.sh`（或开发者工具右键该函数"上传并部署"）
4. 验证：开发者工具本地调用 + 核心路径冒烟（登录→录单→分拣→出库→收款）
5. 回滚后把线上态与 git 差异写进 CHANGELOG，为故障 commit 建 P0/P1 任务卡再正式修

## 4. 小程序版本回退（微信版本管理）

1. 微信公众平台 → 版本管理：体验版异常 → 回退到上一线上版本（"回退版本"入口，仅已发布版本可退）
2. 已发布版本出 P0：立即提紧急修复走快速审核（说明 P0 影响面），同时群内公告临时绕行方式
3. 回退后冒烟：登录→录单→分拣→出库→收款→打印/转发 全路径真机过一遍

## 5. QA 模拟身份紧急关闭

回归测试会临时打开云函数 env QA_IMPERSONATE=1。线上发现某函数带 QA 残留身份（日志里 openid 异常/越权）→ P0：
1. `node tests/qa-toggle.js off`（全部函数置空）
2. `node tests/qa-toggle.js status` 复核全部为空
3. 该函数近期调用记录逐条核查是否被冒名操作

## 6. 事后闭环（P0/P1 必须做，P2 建议做）

1. 观察期：处置后至少 24h 复查核心路径 + 错误日志，无复发才算闭环
2. 复盘：根因（人/代码/流程）写进项目 CHANGELOG 对应版本条目
3. 经验回灌：新坑 append ~/.codex/knowledge/errors.md（日期|现象|根因|修复|项目|复发?）；同类第二次出现必须标复发并给根治方案
4. 根因属流程类：L2 规则候选写 ~/codex-rules/pending/ 待人工确认
5. 任务卡：docs/reports/ 对应任务卡销项（状态=已做+commit）
