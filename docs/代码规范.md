# 丰淮商贸采购下单助手 — 代码规范

> **配套总纲**：[开发规范.md](./开发规范.md)
> **适用范围**：微信小程序端 / Web 管理后台 / 云函数
> **核心原则**：代码是写给人看的，机器只是顺便能跑。

## 1. 命名规范

命名是代码可读性的 80%。名字起对了，代码不用注释也能看懂。

### 1.1 总则

| 类型 | 风格 | 示例 |
|------|------|------|
| 变量、函数 | camelCase 小驼峰 | `orderList`、`submitOrder()` |
| 常量 | UPPER_SNAKE_CASE 全大写下划线 | `MAX_PAGE_SIZE`、`API_BASE_URL` |
| 组件 | PascalCase 大驼峰 | `OrderCard.vue`、`ProductList.vue` |
| Vue 响应式变量 | camelCase + `Ref` 后缀 | `orderListRef`、`loadingRef` |
| 文件名 | 小写连字符 kebab-case（小程序/普通文件） / PascalCase（Vue 组件文件） | `order-list.vue`、`request.js` |
| 云函数名 | 小写连字符 | `create-order`、`get-product-list` |
| 集合名（数据库） | 小写复数 | `orders`、`products`、`customers` |

### 1.2 命名「要」与「不要」

✅ 要：见名知意
```js
// 好
const unpaidOrders = orders.filter(o => o.status === 'draft')
function calculateOrderTotal(items) { ... }

// 不好
const arr = orders.filter(o => o.s === 1)   // s 是什么？1 是什么？
function calc(d) { ... }                     // calc 什么？d 什么？
```

✅ 要：用业务术语，不用技术缩写
```js
// 好（业务方听得懂）
const customerName = order.customer.name
// 不好
const cn = o.c.n
```

❌ 不要：拼错的、缩写到没人认识的、`temp`/`data`/`info` 这种无信息词

### 1.3 布尔变量命名

用 `is/has/can/should` 开头：
```js
const isLoggedIn = false      // ✅
const hasPermission = true    // ✅
const canEdit = false         // ✅
const login = false           // ❌ 是登录状态？还是登录动作？
```

## 2. 代码风格

### 2.1 缩进与格式

- 统一 **2 空格缩进**（小程序、Vue、JS 全统一）
- 行尾不加分号（Vue/JS 项目风格，减少视觉噪音）
- 单引号 `'` 优先，字符串拼接用模板字符串 `` ` ` ``
- 行宽不超过 100 字符

```js
// ✅ 推荐
const greeting = `你好，${customerName}，订单号 ${orderNo}`

// ❌ 避免
const greeting = '你好，' + customerName + '，订单号 ' + orderNo
```

### 2.2 等号与比较

- 永远用 `===` / `!==`，不用 `==` / `!=`（避免隐式类型转换的坑）
- 判空用显式写法

```js
// ✅
if (orderList.length === 0) { ... }
if (name === '' || name === null || name === undefined) { ... }

// 简化判空（推荐）
if (!name) { ... }              // 空字符串、null、undefined 都为 true
if (orderList.length) { ... }   // 有内容才执行
```

### 2.3 ES6+ 用法（本项目默认 ES6+）

| 特性 | 用 | 不用 |
|------|----|----|
| 变量声明 | `const`（默认）/ `let`（需重新赋值） | `var` |
| 字符串 | 模板字符串 `` ` `` | 字符串拼接 `+` |
| 函数 | 箭头函数 `=>`（回调场景） | function（除非需要 this） |
| 导入导出 | `import` / `export` | `require`（云函数 Node 例外，按需） |
| 解构 | `const { name, phone } = customer` | `customer.name`、`customer.phone` 重复取 |
| 默认参数 | `function fn(page = 1)` | 函数内 `if (!page) page = 1` |

## 3. Vue 3 规范（Web 管理后台）

### 3.1 必须用 Composition API + `<script setup>`

```vue
<!-- ✅ 正确：script setup 语法糖 -->
<script setup>
import { ref, computed, onMounted } from 'vue'
import { getOrderList } from '@/api/order'

// 响应式变量：ref + Ref 后缀
const orderListRef = ref([])
const loadingRef = ref(false)
const pageRef = ref(1)

// 计算属性
const totalRef = computed(() => orderListRef.value.length)

// 方法
async function loadOrders() {
  loadingRef.value = true
  try {
    const res = await getOrderList({ page: pageRef.value })
    orderListRef.value = res.data
  } catch (error) {
    console.error('加载订单失败', error)
  } finally {
    loadingRef.value = false
  }
}

onMounted(loadOrders)
</script>
```

❌ 禁止用 Options API（`data()`、`methods`、`computed` 老写法）

### 3.2 组件规范

- 组件名 PascalCase：`OrderCard.vue`
- props 用 `defineProps` + 对象类型声明
- 事件用 `defineEmits`
- 一个组件只做一件事，超过 300 行考虑拆分

```vue
<script setup>
const props = defineProps({
  order: { type: Object, required: true },
  canEdit: { type: Boolean, default: false }
})
const emit = defineEmits(['edit', 'delete'])
</script>
```

### 3.3 样式规范

- 用 `scoped` 隔离样式，避免污染全局
- 类名 kebab-case：`.order-card`、`.btn-primary`
- 颜色、间距抽到 CSS 变量或 Element Plus 主题，不散落硬编码

```vue
<style scoped>
.order-card {
  padding: 16px;
  border-radius: 8px;
}
</style>
```

## 4. 小程序端规范

### 4.1 页面结构

每个页面 4 个同名文件：
```
pages/order/list/
├── list.js        # 逻辑
├── list.wxml      # 结构
├── list.wxss      # 样式
└── list.json      # 页面配置
```

### 4.2 数据绑定与 setData

- 小程序用 `data` + `setData`，**不要一次性 setData 大对象**
- 多次更新合并成一次 setData

```js
// ✅ 合并更新
this.setData({ orderList: list, loading: false, total: list.length })

// ❌ 分多次（性能差）
this.setData({ orderList: list })
this.setData({ loading: false })
this.setData({ total: list.length })
```

### 4.3 云函数调用统一封装

所有云函数调用走 `services/` 封装，不在页面里直接 `wx.cloud.callFunction`：

```js
// services/order.js
export function callOrder(action, data = {}) {
  return wx.cloud.callFunction({
    name: 'order',
    data: { action, ...data }
  }).then(res => res.result)
}

// 页面里使用
import { callOrder } from '../../services/order.js'
const res = await callOrder('create', { customerId, items })
```

## 5. 云函数规范（Node.js）

### 5.1 结构

每个云函数一个目录：
```
cloudfunctions/order/
├── index.js       # 入口
├── package.json
└── utils/         # 函数内工具
```

### 5.2 入口模板（action 路由模式）

```js
// index.js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })

// 路由表：action → handler
const handlers = {
  'create': createOrder,
  'getList': getOrderList,
  'detail': getOrderDetail
}

exports.main = async (event, context) => {
  const { action, ...params } = event
  const handler = handlers[action]
  if (!handler) {
    return { code: 400, message: `未知 action: ${action}` }
  }
  try {
    const data = await handler(params, context)
    return { code: 0, data, message: 'ok' }
  } catch (error) {
    console.error(`[order.${action}] error:`, error)
    return { code: 500, message: error.message || '服务器错误' }
  }
}

async function createOrder(params, context) {
  // 业务逻辑
}
```

### 5.3 返回结构统一

所有云函数返回必须三段式：
```js
{ code: 0, data: {}, message: 'ok' }
// code: 0 成功，非 0 失败
// data: 业务数据
// message: 提示信息
```

### 5.4 数据库操作

- 用 `cloud.database()` 操作
- 查询必须有 `limit`（默认 20，最大 100），防止拉爆
- 写操作必须有**入参校验**
- 删除用软删除（加 `isDeleted: true` 字段），不真删

## 6. 请求与错误处理规范

### 6.1 Web 后台统一 request.js（强制）

**禁止**在业务代码里直接用 `fetch` / `axios`，统一走 `src/request.js`：

```js
// src/request.js
import axios from 'axios'
import { ElMessage } from 'element-plus'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
})

// 响应拦截：统一处理 code
request.interceptors.response.use(
  (response) => {
    const { code, data, message } = response.data
    if (code === 0) return data
    ElMessage.error(message || '请求失败')
    return Promise.reject(new Error(message))
  },
  (error) => {
    ElMessage.error('网络错误，请稍后重试')
    return Promise.reject(error)
  }
)

export default request
```

### 6.2 所有异步必须有 try/catch

```js
// ✅
async function loadOrders() {
  try {
    const data = await getOrderList()
    orderListRef.value = data
  } catch (error) {
    console.error('加载订单失败', error)
    ElMessage.error('加载订单失败')
  } finally {
    loadingRef.value = false
  }
}

// ❌ 裸 await，错误没人接
async function loadOrders() {
  const data = await getOrderList()
  orderListRef.value = data
}
```

### 6.3 错误码约定

| code | 含义 | 前端处理 |
|------|------|----------|
| 0 | 成功 | 取 data 用 |
| 400 | 参数错误 | 提示 message |
| 401 | 未登录 | 跳登录页 |
| 403 | 无权限 | 提示无权限 |
| 500 | 服务器错误 | 提示稍后重试 |

## 7. 注释规范

**原则**：注释解释「为什么」，不解释「是什么」（代码本身能说明的别注释）。

### 7.1 必须注释的场景

- 文件头：文件作用（1 行）
- 函数：复杂函数说明参数、返回值
- 业务规则：如「调货商品 SKU 以 93 开头」
- TODO/FIXME：标记待办

### 7.2 注释风格

```js
/**
 * 计算订单总金额（含件价/零价双轨计算）
 * @param {Array} items - 订单商品列表
 * @returns {number} 总金额（分）
 */
function calculateOrderTotal(items) {
  // 调货商品（93 开头）价格由下单员填写，不走标准价
  // 业务规则见 PRD REQ-订单-012
  ...
}

// TODO: v0.2 接入会员价
// FIXME: 大订单（>100 项）时性能待优化
```

### 7.3 不要写的注释

```js
// ❌ 废话注释
const count = 0  // 把 count 设为 0
// 循环数组
for (let i = 0; i < list.length; i++) { ... }
```

## 8. 安全规范

- **密钥、AppID、环境ID 一律走环境变量**，不硬编码
- 用户输入必须校验：长度、类型、特殊字符
- 数据库查询用参数化，不拼字符串 SQL（云开发 NoSQL 也注意 `$where` 注入）
- 权限校验在云函数里做，**不信任前端传来的角色**
- 日志不打印用户密码、手机号等敏感信息（脱敏）

```js
// ✅
const phone = maskPhone(user.phone)  // 138****1234
console.log('用户手机:', phone)

// ❌
console.log('用户手机:', user.phone)
```

## 9. 性能规范（小白版）

| 场景 | 规则 |
|------|------|
| 列表查询 | 必须分页，默认 20 条/页 |
| 图片 | 云存储压缩，列表用缩略图，详情用原图 |
| setData（小程序） | 合并更新，不传大对象 |
| 云函数 | 避免循环里查数据库（N+1 问题） |
| 防抖节流 | 搜索输入、按钮提交加防抖，防止重复请求 |
