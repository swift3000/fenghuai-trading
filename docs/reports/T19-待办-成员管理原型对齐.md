# T19 待办：成员管理页对齐原型（一/二/三级）

状态：已做（2026-08-20 销项）

## 差异清单（原型 docs/ui/丰淮商贸采购下单助手_原型.html 为基准）
1. 【一级】成员列表：原型=按角色分组（下单员/分拣员/库管/管理员），组头=角色标签+N人+「＋ 添加成员」按钮；成员行=首字头像(角色色)+姓名(+待确认)+openid·手机+✕删除。小程序现状=扁平卡片+切换/移除文字 → 重做为分组列表
2. 【二级】添加成员弹窗：原型=弹窗（姓名/角色/微信openid选填/手机号选填/确认添加）；openid 填=直接激活，空=pending 待确认。小程序完全缺失 → 新增 modal
3. 【三级】权限矩阵：原型「角色权限配置」sec-head 可点击折叠展开（▾ 箭头）。小程序=常驻 → 加折叠
4. 【后端】users.add 不支持 openid 字段（原型二级弹窗有该字段）→ 加 openid 选填+status 联动
5. 【后端】users.remove 拒绝删任何 admin；原型=「至少保留一名管理员，可删多余 admin」→ 改为计数保护
6. 【测试】wx-perm-ui-test.js 取页逻辑：getCurrentPages() 末位偶发取到已销毁 webview 页 → 改按 route 找 members 页+重试（已发现 bug，待修）

## 决策
- 角色头像色=角色标签色（orderer 绿 #67C23A / sorter 橙 #F8A44C / warehouse 蓝 #409EFF / admin 红 var(--red)）；原型 p.color 本身未定义（原型小 bug），以标签色为事实口径
- 保留小程序的「切换角色」能力（后端 update-role 既有，测试已覆盖），原型无此入口不强制加
- 移除保护口径对齐原型：非 admin 可删；admin 删除时若剩余 admin≤1 拒绝
