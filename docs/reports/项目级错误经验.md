### E-001 同一文件并行 SearchReplace 写竞态，修改被静默覆盖

| 项 | 内容 |
|----|------|
| **日期** | 2026-08-03 |
| **现象** | 对同一文件**并行**提交多个 SearchReplace 编辑时，diff 全部显示"修改成功"，但实际只有部分修改生效，其余被后面的写入静默覆盖。多处修改丢失后才发现：如订单号前缀"FH-"改"丰淮商贸-"、商品默认数量0、排序代码等被还原为旧值。4个文档（PRD/ERD/API/TDD）和 UI 原型均出现此问题。 |
| **根本原因** | 同一文件的多个并行编辑基于同一旧版本计算 diff，后写入的覆盖先写入的（最后写入者胜），导致前面已成功的修改丢失；工具返回成功但内容未保留，具有欺骗性。 |
| **解决方案** | **对同一文件的多次编辑必须串行执行**（一次只发一个 SearchReplace，确认生效后再改下一处）；不同文件之间可以并行。修改完成后必须用 Grep/Read **复查关键字段是否真实落盘**，不能只信 diff 提示。 |
| **影响范围** | 所有文档/代码批量修改场景。检查清单：改完 grep 验证关键数字/字段名/枚举值在各处一致（与"改代码同步改文档"门禁结合执行）。 |

### E-002 @cloudbase/node-sdk 直连 DB 的 API 口径坑（与 wx-server-sdk 不同）

| 项 | 内容 |
|----|------|
| **日期** | 2026-08-20 |
| **现象** | node-sdk 直连脚本连续报错：db.RegExp(位置参数) 报 regexp must be a string；_.regexp 报 not a function；add({data:{...}}) 写出 {data:{...}} 嵌套脏结构；doc(id).get() 返回的 .data 是数组。 |
| **根本原因** | node-sdk 与 wx-server-sdk 口径不同：db.RegExp 只接受单对象 {regexp:<非空string>,options}（空串也抛错，需判空再拼 or）；_.regexp 只在云函数 wx-server-sdk 里有；node-sdk add() 直接传平铺文档（传 {data:x} 会把 data 当字段名写入）；doc().get()/collection().get() 的 .data 都是数组需 [0] 解包。 |
| **解决方案** | node-sdk 脚本统一：db.RegExp({regexp:esc(str),options:"i"}) 且字段值为空时不加入 or 条件；搜索词先 esc 转义正则特殊字符（商品名含 +/(/. 等，不转义会漏搜）；写入 coll.add(flatDoc) 取返回 .id（不是 _id）；回读 const r=await coll.doc(id).get(); const doc=Array.isArray(r.data)?r.data[0]:r.data;。参考实现 tests/validate-products-customers.js（T18）。 |
| **影响范围** | 所有 node-sdk 直连脚本（校验/清理/回归）。业务读写走云函数（wx-server-sdk 口径 {data:x} + _.regexp），两套口径不得混用，与 AGENTS.md 已知坑"set 口径混用写脏结构"同源。 |
