## 1. 概述

### 1.1 文档目的

本文档旨在为「丰淮商贸采购下单助手」微信小程序项目建立统一的开发规范，达成以下目标：

- **统一编码风格**：消除团队成员之间的代码风格差异，降低阅读成本
- **保证代码质量**：通过规范约束减少低级错误，提升代码可靠性
- **提升可维护性**：使代码结构清晰、命名一致，方便后续迭代和交接
- **加速协作效率**：新成员可依据本文档快速上手项目开发

### 1.2 适用范围

本规范适用于项目全部代码，包括：

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| 前端 | 微信原生小程序 + TypeScript + Vant Weapp | 小程序页面、组件、样式 |
| 后端 | 微信云开发（云函数，Node.js） | 共 10 个云函数：auth、products、customers、orders、users、regions、receivable、system、report、smart |
| 数据库 | 云开发数据库（MongoDB） | 11 个集合：users、products、customers、orders、order_items、regions、payments、product_aliases、customer_aliases、order_logs、system_config |
| 打印 | ESC/POS 蓝牙 BLE | 小票打印、分拣单打印 |

### 1.3 基本原则

1. **可读性优先**：代码是写给人看的，其次才是给机器执行的
2. **约定优于配置**：遵循团队约定，减少不必要的配置和特殊处理
3. **防御性编程**：对外部输入保持不信任，做好校验和异常处理
4. **最小权限原则**：前端只请求必要的数据，云函数只开放必要的操作

### 2.2 目录职责说明

| 目录 | 职责 | 约束 |
|------|------|------|
| `pages/` | 页面文件，每个页面包含 `.js` `.json` `.wxml` `.wxss` 四件套 | 页面间不直接引用，通过路由跳转 |
| `components/` | 可复用组件 | 不依赖具体页面数据，通过 properties 传入 |
| `utils/` | 纯工具函数，无 UI 依赖 | 可被页面和组件自由引用 |
| `constants/` | 常量定义 | 只导出只读常量，禁止在常量文件中写逻辑 |
| `styles/` | 公共样式 | 使用 `@import` 引入，不直接复制样式代码 |

### 2.3 文件组织规则

1. **单文件不超过 400 行**：超过则拆分为子模块或子函数
2. **一个文件一个职责**：`utils/format.js` 只做格式化，不混入校验逻辑
3. **引用路径不超过 3 层**：超过说明目录结构需要调整
4. **组件目录必须包含**：`index.js` `index.json` `index.wxml` `index.wxss` `README.md`（可选）

## 3. 命名规范

### 3.1 命名规则总览

| 类别 | 规则 | 示例 | 反例 |
|------|------|------|------|
| 页面目录 | kebab-case | `new-order`, `order-detail` | `newOrder`, `NewOrder` |
| 组件名（JS 注册） | PascalCase | `OrderCard`, `ProductPicker` | `order-card`, `orderCard` |
| 组件目录 | kebab-case | `order-card/`, `product-picker/` | `OrderCard/` |
| JS 变量 / 函数 | camelCase | `orderList`, `handleSubmit` | `order_list`, `HandleSubmit` |
| 常量 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE`, `ORDER_STATUS` | `maxPageSize`, `order-status` |
| 数据库集合名 | 小写复数 | `orders`, `products`, `customers` | `order`, `ProductList` |
| 数据库字段名 | snake_case | `created_at`, `material_code`, `unit_price` | `createdAt`, `materialCode` |
| 云函数名 | 小写单词 | `auth`, `products`, `orders` | `getProducts`, `Auth` |
| 云函数 action | camelCase | `createOrder`, `updateStatus`, `matchProduct` | `create_order`, `Updatestatus` |
| CSS 类名 | BEM 命名法 | `.order-card__item--active` | `.orderCardItem`, `.active` |
| 文件名（工具） | kebab-case | `format.js`, `validator.js` | `Format.js`, `myUtils.js` |

### 3.2 BEM 命名详解

```
.块(block)           → .order-card
.块__元素(element)    → .order-card__item
.块__元素--修饰符     → .order-card__item--active
.块--修饰符           → .order-card--disabled
```

实际示例：

```css
/* 订单卡片 */
.order-card { }
.order-card__header { }
.order-card__body { }
.order-card__item { }
.order-card__item--highlight { }
.order-card__footer { }
.order-card--disabled { }
```

### 3.3 语义化命名要求

- **变量名表达"是什么"**：`orderList`、`totalAmount`、`currentUser`
- **函数名表达"做什么"**：`getOrderList`、`calculateTotal`、`submitOrder`
- **布尔变量加前缀**：`isLoading`、`hasPermission`、`canEdit`
- **事件处理加 handle**：`handleTap`、`handleSubmit`、`handleDelete`
- **禁止无意义命名**：`data1`、`tempList`、`handleClick2`

## 4. 小程序前端编码规范

### 4.1 WXML 规范

```xml
<!-- ✅ 正确示例 -->
<view class="order-card">
  <view class="order-card__header">
    <text class="order-card__title">{{orderTitle}}</text>
    <text class="order-card__status order-card__status--{{statusClass}}">
      {{statusText}}
    </text>
  </view>
  <view class="order-card__body">
    <view class="order-card__item" wx:for="{{orderItems}}" wx:key="_id">
      <text>{{item.productName}}</text>
      <text class="order-card__price">¥{{item.formattedPrice}}</text>
    </view>

<!-- ❌ 错误示例 -->
<view class='order-card'>          <!-- 属性用单引号 -->
<view class=order-card>            <!-- 属性没加引号 -->
<view hidden={{!show}}>            <!-- 布尔属性未显式写 -->
<text>{{a > b ? (c + d) : list[0].name}}</text>  <!-- 模板中写复杂表达式 -->
```

**WXML 规则清单**：

| 规则 | 说明 |
|------|------|
| 缩进 2 空格 | 不使用 Tab，保持层级清晰 |
| 属性值用双引号 | `class="xxx"` 而非 `class='xxx'` |
| 布尔属性显式写 | `hidden="{{true}}"` 而非省略 |
| `wx:key` 必写 | 列表渲染必须指定唯一 key |
| 模板不写复杂逻辑 | 超过一个运算符的表达式移到 JS 中处理 |
| 条件渲染用 `wx:if` / `wx:else` | 频繁切换用 `hidden`，条件分支多用 `wx:if` |

### 4.3 JavaScript / TypeScript 规范

```javascript
// ✅ 正确示例
const MAX_PAGE_SIZE = 50;
const ORDER_STATUS_MAP = {
  draft: '草稿',
  submitted: '待分拣',
  sorted: '已分拣',
  confirmed: '已出库',
  completed: '已完成',
  cancelled: '已取消',
  rejected: '已驳回',
};

Page({
  data: {
    orderList: [],
    isLoading: false,
    currentPage: 1,
    hasMore: true,
  },

  onLoad(options) {
    this._initPage(options);
  },

  onShow() {
    this._refreshData();
  },

  onUnload() {
    this._cleanup();
  },

  async _initPage(options) {
    this.setData({ isLoading: true });
    try {
      const res = await this._fetchOrders(1);
      this.setData({
        orderList: res.data.list,
        hasMore: res.data.list.length >= MAX_PAGE_SIZE,
      });
    } catch (err) {
      console.error('[orders] 加载订单列表失败:', err);
      wx.showToast({ title: '加载失败', icon: 'none' });
    } finally {
      this.setData({ isLoading: false });
    }
  },

  async _fetchOrders(page) {
    return await request('orders', {
      action: 'getOrderList',
      page,
      pageSize: MAX_PAGE_SIZE,
    });
  },

  async _refreshData() {
    await this._initPage({});
  },

  _cleanup() {
    // 清理定时器、事件监听等
  },
});
```

**JS/TS 规则清单**：

| 规则 | 说明 |
|------|------|
| 使用 `const` / `let` | 禁止 `var`，优先 `const`，需修改时用 `let` |
| 使用 `async/await` | 替代 `.then()` 链式调用，配合 `try/catch` 处理错误 |
| 私有方法加下划线前缀 | `_initPage`、`_fetchOrders` 表示内部方法 |
| 事件函数用 `handle` 前缀 | `handleTap`、`handleSubmit`、`handleDelete` |
| 避免直接修改 `this.data` | 统一使用 `this.setData()` |
| 合并 `setData` 调用 | 多次赋值合并为一次 `setData`，减少渲染开销 |
| 字符串用模板字面量 | `` `订单${orderNo}` `` 而非 `'订单' + orderNo` |
| 对象解构赋值 | `const { name, phone } = customer;` |

### 4.4 页面生命周期规范

```
onLoad(options)
  └─ 接收路由参数，初始化页面数据
  └─ 只执行一次

onShow()
  └─ 刷新列表数据（从其他页面返回时触发）
  └─ 每次页面显示都会执行

onReady()
  └─ 页面初次渲染完成，可操作 DOM（如创建 canvas 上下文）

onHide()
  └─ 页面隐藏时暂停定时器、停止动画

onUnload()
  └─ 页面卸载时清理：定时器、事件监听、WebSocket 连接
```

**生命周期规则**：

| 生命周期 | 应该做 | 禁止做 |
|----------|--------|--------|
| `onLoad` | 接收参数、初始化数据、发起首次请求 | 操作 DOM、创建动画 |
| `onShow` | 刷新数据、恢复状态 | 重复初始化已在 `onLoad` 完成的工作 |
| `onReady` | 操作 DOM、创建 canvas 上下文 | 发起网络请求（应提前到 onLoad） |
| `onHide` | 暂停定时器、停止视频播放 | 清除数据（页面可能还会回来） |
| `onUnload` | 清理所有资源 | 发起新的网络请求 |

### 4.5 数据绑定规范

```javascript
// ❌ 禁止：在模板中写复杂表达式
// WXML: <text>{{order.items.map(i => i.price).reduce((a,b) => a+b, 0)}}</text>

// ✅ 正确：在 JS 中预处理
const totalAmount = order.items.reduce((sum, item) => sum + item.price, 0);
this.setData({
  formattedTotal: `¥${totalAmount.toFixed(2)}`,
});
// WXML: <text>{{formattedTotal}}</text>
```

**数据绑定规则**：

1. 模板中只做简单的属性访问：`{{item.name}}`
2. 简单格式化可用 WXS：`{{filters.formatPrice(item.price)}}`
3. 复杂计算必须在 JS 中完成后再 `setData`
4. 避免在 `setData` 中传递大量无用数据，只传模板需要的字段

### 4.6 事件处理规范

```javascript
// ✅ 事件处理函数统一格式
handleOrderTap(event) {
  const { id } = event.currentTarget.dataset;
  wx.navigateTo({
    url: `/pages/order-detail/order-detail?id=${id}`,
  });
},

handleSubmit() {
  if (this.data.isSubmitting) return;  // 防重复提交
  this.setData({ isSubmitting: true });
  // ... 提交逻辑
},

handleDelete(event) {
  const { id, name } = event.currentTarget.dataset;
  wx.showModal({
    title: '确认删除',
    content: `确定要删除「${name}」吗？`,
    success: (res) => {
      if (res.confirm) {
        this._doDelete(id);
      }
    },
  });
},
```

**事件处理规则**：

| 规则 | 说明 |
|------|------|
| 函数名 `handle` 前缀 | 区分事件处理和内部方法 |
| 防重复提交 | 提交类操作加 `isSubmitting` 标志位 |
| 使用 `dataset` 传参 | `data-id="{{item.id}}"`，在事件中通过 `event.currentTarget.dataset.id` 获取 |
| 删除操作二次确认 | 必须使用 `wx.showModal` 确认 |

### 4.7 请求封装规范

所有云函数调用必须通过 `utils/request.js` 统一封装：

```javascript
// utils/request.js
const request = async (functionName, params = {}) => {
  try {
    const res = await wx.cloud.callFunction({
      name: functionName,
      data: params,
    });

    const { code, data, message } = res.result;

    if (code !== 0) {
      console.warn(`[request] ${functionName} 业务错误:`, code, message);
      wx.showToast({ title: message || '操作失败', icon: 'none' });
      return Promise.reject({ code, message });
    }

    return { code, data, message };
  } catch (err) {
    console.error(`[request] ${functionName} 调用失败:`, err);
    wx.showToast({ title: '网络异常，请重试', icon: 'none' });
    return Promise.reject(err);
  }
};

module.exports = request;
```

**请求规则**：

1. 页面中禁止直接调用 `wx.cloud.callFunction`
2. 统一通过 `request(云函数名, { action, ...params })` 调用
3. 错误处理在 `request.js` 中统一做，页面只处理业务逻辑
4. 需要特殊错误处理的场景，在 `catch` 中单独处理

## 5. 云函数编码规范

### 5.1 统一入参结构

所有云函数接收统一格式的参数：

```javascript
// 客户端调用
wx.cloud.callFunction({
  name: 'orders',
  data: {
    action: 'createOrder',     // 必须：指定操作类型
    customerId: 'xxx',         // 业务参数
    items: [...],
    remark: '尽快发货',
  },
});
```

### 5.2 统一出参结构

所有云函数返回统一格式：

```javascript
// 成功
return {
  code: 0,
  data: {
    orderId: 'xxx',
    orderNo: 'ORD20260810001',
  },
  message: '创建成功',
};

// 失败
return {
  code: 1001,
  data: null,
  message: '客户ID不能为空',
};
```

### 5.3 错误码规范

| 错误码范围 | 类型 | 说明 | 示例 |
|-----------|------|------|------|
| `0` | 成功 | 操作成功 | — |
| `1000-1999` | 参数错误 | 缺少必填参数、格式不正确 | `1001` 缺少客户ID |
| `2000-2999` | 业务错误 | 业务规则校验不通过 | `2001` 库存不足 |
| `3000-3999` | 权限错误 | 无权执行该操作 | `3001` 非管理员禁止删除 |
| `5000-5999` | 系统错误 | 服务器内部异常 | `5001` 数据库写入失败 |

### 5.4 云函数代码结构

```javascript
// cloudfunctions/orders/index.js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();
const _ = db.command;

// action 路由
exports.main = async (event, context) => {
  const { action } = event;
  const { OPENID } = cloud.getWXContext();

  switch (action) {
    case 'createOrder':
      return await createOrder(event, OPENID);
    case 'getOrderList':
      return await getOrderList(event, OPENID);
    case 'getOrderDetail':
      return await getOrderDetail(event, OPENID);
    case 'updateStatus':
      return await updateStatus(event, OPENID);
    case 'updatePrice':
      return await updatePrice(event, OPENID);
    default:
      return { code: 1000, data: null, message: `未知 action: ${action}` };
  }
};

// 每个 action 一个独立函数
async function createOrder(event, openid) {
  const { customerId, items, remark } = event;

  // 1. 参数校验
  if (!customerId) {
    return { code: 1001, data: null, message: '客户ID不能为空' };
  }
  if (!items || !Array.isArray(items) || items.length === 0) {
    return { code: 1001, data: null, message: '订单商品不能为空' };
  }

  // 2. 权限校验
  const userRole = await getUserRole(openid);
  if (!['admin', 'orderer', 'sorter', 'warehouse'].includes(userRole)) {
    return { code: 3001, data: null, message: '无权创建订单' };
  }

  // 3. 业务逻辑
  try {
    const orderNo = await generateOrderNo();
    const orderData = {
      order_no: orderNo,
      customer_id: customerId,
      items: items,
      status: 'submitted',
      total_amount: calculateTotal(items),
      remark: remark || '',
      created_by: openid,
      created_at: db.serverDate(),
      updated_at: db.serverDate(),
    };

    const result = await db.collection('orders').add({ data: orderData });

    console.log(`[orders] 创建订单成功: ${orderNo}, 操作人: ${openid}`);

    return {
      code: 0,
      data: { orderId: result._id, orderNo },
      message: '创建成功',
    };
  } catch (err) {
    console.error('[orders] 创建订单失败:', err);
    return { code: 5001, data: null, message: '创建订单失败，请重试' };
  }
}

// 超过 30 行的逻辑拆分为子函数
function calculateTotal(items) {
  return items.reduce((sum, item) => {
    return sum + item.unit_price * item.quantity;
  }, 0);
}

async function generateOrderNo() {
  const now = new Date();
  const dateStr = now.toISOString().slice(0, 10).replace(/-/g, '');
  const random = String(Math.floor(Math.random() * 1000)).padStart(3, '0');
  return `ORD${dateStr}${random}`;
}

async function getUserRole(openid) {
  const res = await db.collection('users')
    .where({ openid })
    .field({ role: true })
    .get();
  return res.data[0]?.role || 'guest';
}
```

### 5.5 云函数编码规则

| 规则 | 说明 |
|------|------|
| 每个 action 一个函数 | 函数体不超过 100 行，超过则拆分子函数 |
| 入参校验放最前 | 先校验参数，再校验权限，最后执行业务 |
| 权限校验第二步 | 每个 action 开头校验 `role` 权限 |
| 数据库操作使用链式调用 | `db.collection().where().field().orderBy().get()` |
| 关键操作记录日志 | `console.log('[模块] 操作描述:', 关键数据)` |
| 错误日志用 `console.error` | 包含错误对象，方便排查 |
| 警告日志用 `console.warn` | 业务异常但非系统错误 |
| 禁止吞掉异常 | `catch` 中必须记录日志或返回错误 |
| 使用 `db.serverDate()` | 时间戳由服务端生成，不信任客户端时间 |

### 5.6 数据库操作规范

```javascript
// ✅ 查询加索引字段
const orders = await db.collection('orders')
  .where({
    customer_id: customerId,
    status: _.in(['submitted', 'sorted', 'confirmed', 'completed']),
    created_at: _.gte(startDate),
  })
  .field({
    order_no: true,
    customer_id: true,
    total_amount: true,
    status: true,
    created_at: true,
  })
  .orderBy('created_at', 'desc')
  .limit(50)
  .get();

// ❌ 禁止全表扫描
const allOrders = await db.collection('orders').get();  // 无 where、无 limit
```

**数据库规则**：

| 规则 | 说明 |
|------|------|
| 查询必须带 `where` | 禁止无条件全表查询 |
| 查询必须带 `limit` | 单次最多 100 条，列表页推荐 20-50 条 |
| 使用 `field` 指定返回字段 | 不返回前端不需要的字段，减少传输量 |
| 高频查询字段建索引 | `customer_id`、`status`、`created_at` 等筛选字段 |
| 批量写入用 `add` 数组 | 单次最多 100 条 |
| 更新用 `doc().update()` | 不用 `where().update()` 批量更新（除非确实需要） |
| 使用事务保证一致性 | 涉及多集合写入时使用事务 |

## 6. Git 规范

### 6.1 分支策略

```
main          ●──────────────────────────────●──── 生产环境
               ╱                              ╱
develop   ●───●──────●───────●───────●──────●───── 开发主线
           ╱      ╱         ╱       ╱
feature/  ●───●──●        ╱       ╱           功能分支
orders-price         ╱            ╱
feature/            ●───●───●    ╱              功能分支
smart-match                    ╲●               功能分支
```

| 分支 | 用途 | 保护规则 |
|------|------|---------|
| `main` | 生产环境代码 | 只接受 `develop` 合并，禁止直接提交 |
| `develop` | 开发主线 | 只接受 `feature/*` 合并，禁止直接提交 |
| `feature/*` | 功能开发 | 从 `develop` 拉出，完成后合并回 `develop` |
| `hotfix/*` | 紧急修复 | 从 `main` 拉出，修复后同时合并到 `main` 和 `develop` |

### 6.2 Commit Message 格式

```
type(scope): description

[可选 body]

[可选 footer]
```

**type 类型**：

| type | 说明 | 示例场景 |
|------|------|---------|
| `feat` | 新功能 | 新增订单改价功能 |
| `fix` | 修复 Bug | 修复智能录入匹配错误 |
| `docs` | 文档更新 | 更新 API 接口文档 |
| `style` | 代码格式 | 调整缩进、空格、换行 |
| `refactor` | 重构 | 提取公共函数、优化结构 |
| `test` | 测试 | 添加测试用例 |
| `chore` | 构建/工具 | 更新依赖、修改配置 |
| `perf` | 性能优化 | 优化列表渲染性能 |

**scope 范围**（可选）：

`orders`、`products`、`customers`、`smart`、`receivable`、`outbound`、`reports`、`auth`、`printer`、`ui`、`api`

**description 描述**：

- 使用中文，简明扼要
- 不超过 50 个字符
- 不以句号结尾

**提交示例**：

```bash
feat(orders): 新增订单内改价功能

fix(smart): 修复智能录入模糊匹配阈值过低问题

docs(api): 更新接口文档，新增 smart.match 接口

refactor(utils): 提取公共格式化函数到 format.js

perf(orders): 优化订单列表渲染，减少 setData 数据量

chore(deps): 升级 vant-weapp 至 1.11.6
```

### 6.3 提交频率与粒度

| 规则 | 说明 |
|------|------|
| 每个功能点一次提交 | 不要攒大量改动一次提交 |
| 一个 commit 只做一件事 | 不要把改 Bug 和新功能混在一起 |
| 提交前确保可运行 | 不要提交编译报错的代码 |
| 提交前检查 `git diff` | 确认没有误提交的调试代码、敏感信息 |

## 8. 性能规范

### 8.1 性能指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 首屏加载时间 | < 2 秒 | 微信开发者工具性能面板 |
| 云函数响应时间 | < 500ms（P95） | 云开发控制台监控 |
| 页面切换时间 | < 300ms | 用户体感 + 性能埋点 |
| 列表滚动帧率 | ≥ 55fps | 开发者工具调试面板 |
| 包体积 | 主包 < 2MB，分包各 < 2MB | 构建产物分析 |

### 8.2 前端性能规则

| 规则 | 说明 |
|------|------|
| 首屏数据预加载 | 在 `onLoad` 中发起请求，不在 `onReady` 才请求 |
| 列表分页加载 | 单次加载不超过 50 条，滚动到底部加载更多 |
| 图片压缩 | 上传前压缩，单张不超过 500KB；列表中使用缩略图 |
| 图片懒加载 | 长列表中使用 `lazy-load` 属性 |
| 合并 `setData` | 多次赋值合并为一次调用 |
| 精简 `setData` 数据 | 只传模板需要的字段，不传整个对象 |
| 使用 `wx:key` | 列表渲染必须指定唯一 key，提升 diff 效率 |
| 避免频繁 `setData` | 输入框用 `bindblur` 而非 `bindinput` 更新数据 |
| 分包加载 | 非首屏页面（报表、成员管理等）放入分包 |
| 减少 `wx:if` 渲染开销 | 频繁切换的元素用 `hidden` 替代 |

### 8.3 云函数性能规则

| 规则 | 说明 |
|------|------|
| 查询带索引字段 | `where` 条件使用已建索引的字段 |
| 查询指定返回字段 | 使用 `field()` 减少数据传输 |
| 批量操作合并 | 多条写入用数组一次 `add`，减少调用次数 |
| 避免循环中查询数据库 | 先批量查出，再在内存中匹配 |
| 合理使用缓存 | 不常变化的数据（区域列表、系统配置）设置缓存 |
| 冷启动优化 | 公共初始化代码放 `cloud.init()` 之后，按需加载模块 |

## 9. 安全规范

### 9.1 前端安全

| 规则 | 说明 |
|------|------|
| 不存储敏感信息 | 禁止在 `wx.setStorage` 中存储密码、密钥 |
| 不信任前端数据 | 所有数据在云函数中重新校验，不信任前端传来的值 |
| 输入长度限制 | 文本输入框设置 `maxlength`，防止超长注入 |
| XSS 防护 | 使用 `{{}}` 绑定数据（自动转义），避免使用 `rich-text` 渲染用户输入 |
| 敏感页面加验证 | 管理员操作（删除商品、修改价格）需二次确认 |

### 9.2 云函数安全

| 规则 | 说明 |
|------|------|
| 校验所有用户输入 | 类型校验、长度校验、范围校验 |
| 权限校验前置 | 每个 action 开头校验 `openid` 和 `role` |
| 使用 `cloud.getWXContext()` | 从微信上下文获取 `OPENID`，不从客户端传入 |
| 参数白名单 | 只接收业务需要的参数，忽略多余字段 |
| 数据库权限规则 | 在云开发控制台配置集合权限 |
| 日志不输出敏感数据 | 日志中不打印手机号完整号码、密码等 |

### 9.3 数据库权限规则

在云开发控制台配置各集合的安全规则：

| 集合 | 权限规则 | 说明 |
|------|---------|------|
| `users` | 管理员可读写全部，用户只能读自己的数据 | 成员信息保护 |
| `products` | 所有登录用户可读，管理员可写 | 商品信息公开 |
| `customers` | 管理员和下单员/分拣员/库管可读，管理员可写 | 客户信息保护 |
| `orders` | 创建者可读写，管理员可读写全部 | 订单数据隔离 |
| `order_items` | 跟随订单权限 | 订单项与订单一致 |
| `regions` | 所有登录用户可读，管理员可写 | 区域数据公开 |
| `system_config` | 仅管理员可读写 | 系统配置保护 |
| `payments` | 管理员可读写全部，下单员/分拣员/库管只能读自己的 | 财务数据保护 |

### 9.4 蓝牙打印安全

| 规则 | 说明 |
|------|------|
| 不打印敏感信息 | 打印小票不包含管理员信息、系统配置等 |
| 打印数据脱敏 | 客户手机号中间四位用 `****` 替代（可选） |
| BLE 连接校验 | 连接前校验设备名称，防止连接到非打印设备 |
