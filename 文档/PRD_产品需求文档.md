## 1.0核心原则（方案A唯一方案）

### 原则1：全员小程序，无Web后台
- ❌ **不做任何Web后台页面**，全员在小程序完成所有操作
- 库管在小程序确认订单、导出Excel；管理员在小程序管理用户/商品/客户

### 原则2：蓝牙打印（1.0必做，核心能力）
- ✅ **蓝牙打印必做**：兼容 ESC/POS 指令集，58mm便携热敏（芯烨/佳博/汉印等主流）
- 下单员提交订单后可一键蓝牙打印送货单
- 订单详情页、订单列表支持打印多张
- 支持多张送货单连续打印

### 原则3：微信云开发（零运维，甲方最少费用）
- ✅ **后端用微信云开发**：云函数 + 云数据库 + 云存储
- 零服务器、零域名、零SSL证书，甲方首年仅约840元
- 运维极简，系统自动扩容

### 原则4：功能闭环，不多不少
- 22项核心功能，刚好覆盖丰淮商贸日常采购送货全流程
- 不做任何锦上添花功能（如消息推送、多仓库、多币种等）

## 2. 产品定位

### 2.1 产品愿景
为丰淮商贸的一线下单员、库管和老板提供一套**超轻量、低成本、即开即用**的小程序下单解决方案，全员使用小程序完成日常操作，一键蓝牙打印送货单，现场交付客户，取代传统纸质单据与手工汇总。

### 2.2 核心价值
1. **现场录单，蓝牙即打**：下单员手机端录单，58mm便携热敏直接打送货单给客户。
2. **全员小程序**：下单、查单、改单、确认、导出全在小程序完成，无需电脑。
3. **数据实时准确**：订单状态、汇总报表实时可见，算钱算量零误差。
4. **零运维最低成本**：微信云开发后端，甲方首年仅840元，无服务器压力。

### 2.3 目标用户
- **下单员（业务员）**：外出拜访客户，现场完成订单录入 + 蓝牙打印送货单。
- **分拣员（理货员）**：仓库内对照订单核对实物，可录入分拣备注（破损/缺货），一键完成分拣（待分拣→已分拣）→ 推给库管出库。
- **库管**：查看已分拣的待出库订单，一步【确认出库】（已分拣→已出库），导出Excel出库单。
- **管理员（老板/内勤）**：维护商品与客户资料、审核订单、打印/导出汇总、管理所有角色账号。

## 3. 用户画像

### 3.1 下单员
- 年龄 25-45 岁，习惯使用微信小程序进行移动办公。
- 关注点：操作快、不丢单、算钱准、蓝牙打印能直接出单。
- 使用场景：客户门店、仓库、车里、家里（补单）。
- 痛点：纸质单易丢、手工算错、回办公室重复录入、现场无单客户不签收。

### 3.2 分拣员（理货员）
- 年龄 28-50 岁，会用微信小程序 + 基础手机操作，**打字能力一般**。
- 关注点：订单一眼能看完、分拣一键完成（待分拣→已分拣）、备注支持常用短语快捷选择。
- 使用场景：仓库分拣台（手机/平板横屏）、冷库。
- 痛点：纸质拣货单容易错漏、拣完要手写签名交单（无追溯）、商品缺货需电话联系下单员反复沟通。

### 3.3 库管
- 年龄 30-50 岁，会用微信小程序 + 基础电脑操作。
- 关注点：出库确认快（一步确认）、导出Excel一键搞定、格式直接能用。
- 使用场景：仓库（小程序确认）、办公室电脑前（导出）。
- 痛点：汇总靠手工、备货单要自己整理。

### 3.3 管理员
- 年龄 30-55 岁，具备基础电脑操作能力。
- 关注点：数据准、能对账、好打印、能导出 Excel。
- 使用场景：办公室电脑前。
- 痛点：汇总靠 Excel、打印格式调半天、历史订单难找。

### 4.2 角色与权限矩阵

> **1.0原则**：全员使用小程序，无Web后台，小程序内完成所有操作。**下单/改单/删单权限给所有人（4角色均可，含订单内自定义价格）；分拣员只读与库管价格脱敏规则取消，全员可见并操作价格。分拣为一键「待分拣→已分拣」，出库为库管一步确认「待出库(已分拣)→已出库」。收款两步：登记收款（`receivable:collect`）→ 确认收款（`receivable:confirm`）。**

### 4.3 小程序（全员使用）详细需求

#### 4.3.1 登录与首页

- **首管理员（方案 A 零配置）**：系统首次启动、库中无任何管理员时，**第一位登录者自动成为 `role=admin`**（login 云函数检测无 admin 即自动赋值）。老板部署后直接用微信打开小程序登录即可，**无需配置任何环境变量、也无需事先知道 openid**；后续成员由管理员在「成员管理」中分配角色。（可选兜底：如需指定特定人为首管理员，可由运维在数据库中手工置 `role=admin`，非主路径。详见《部署运维文档》§3.6）
- **登录后默认跳转**：
  - 分拣员 → 自动跳「分拣出库」（分拣段-待分拣 默认）
  - 库管 → 自动跳「分拣出库」（出库段-待出库 默认）
  - 下单员/管理员 → 首页
- **首页**：
  - 顶部状态卡：今日下单数/今日待分拣/今日已分拣/今日待出库/今日已出库/今日收款金额（按角色隐藏不相关）
  - 展示"今日订单/今日金额/待处理"统计卡、"新建订单/订单查询"入口卡片、"赊销看板/报表中心"入口。
  - **右下角悬浮球（2026-08-17 新增）**：主球为「智能录入」入口（点击弹层：文字录入/语音占位），旁挂小图标球；位置在内容区右下、TabBar 上方。
- **底部Tab栏（4角色完全一致，1.0 开放权限模型：不再按角色隐藏）**：
  - 📋首页 / 📦订单 / ＋(中央凸起「新建订单」按钮) / 🏭工作台 / 👤我的（共 **4 个 Tab + 中央新建按钮**，custom-tab-bar；工作台页内按角色分发：分拣员→分拣作业、库管→出库作业、其余→赊销看板/报表入口；报表入口置于「我的 → 报表统计」，不单独占 Tab）

  - 通用菜单：蓝牙打印设置 / 商品管理 / 客户管理 / 报表统计 / 字体大小 / 成员管理* / 系统设置* / 退出登录

#### 4.3.2 录单流程（核心）
1. **选客户**
   - 支持按区域分组浏览、关键字搜索（客户名/拼音/电话）。
   - 常用客户置顶（最多 10 个）。
   - 新增客户入口：录单时可直接新增客户。
2. **选商品（1.0：单栏 + 选品弹窗）**
   - 录单页采用**单栏布局**：上方为「请选择客户」，下方为订单明细（已选商品+数量+金额），点击「+ 添加商品」打开选品弹窗（1.0 起取消「收款方式」选择，所有新建订单统一默认未付款）。
   - 选品弹窗：**无搜索词时仅展示前 3 个常购商品**（按该客户历史订单常购次数降序），**输入搜索词后展示全部匹配商品**（"通过搜索商品来获取列表"）；支持商品名/料号/拼音搜索。
   - **排序规则**：先按「固定商家（客户）维度常购次数」降序优先（该客户历史订单中购买越多的商品越靠前），其次按全局使用频率 products.usage 降序（选择越多的越靠前，习惯养成）。
   - 展示商品名称、规格、件价、包价。
   - 新增商品入口：录单时可直接新增商品。
3. **选客户自动带出上次订单（1.0新增，核心提效）**
   - 新建订单选择客户后，若该系统有该客户的历史订单，将**自动带出上次订单的全部商品与数量**到当前订单明细（价格沿用上次成交价），下单员可直接在此基础上**手动修改数量、改价、删除或继续添加商品**。
   - 带出的商品行标记「预填」徽标，提示该数据来自上次订单、需核对；数量与价格均可编辑，编辑不会影响历史订单。
   - 编辑已有订单（进入编辑模式）时不触发自动带出，保留原订单明细。
   - 客户无历史订单时为空，由下单员手动添加。
4. **填写数量**
   - 双轨录入：**件数 + 包数**（件为大单位，包为小单位，如 1 件 = 24 包；默认单位「包」，去掉"零"字）。
   - **手动添加商品时数量默认 0**；**自动带出的上次订单商品保留原数量**，由下单员核对后调整，避免误录。
   - **输入框加大**：件数/包数输入框采用大号字体、加宽加高，便于现场快速录入。
   - 实时计算金额：`件数 × 件价 + 包数 × 包价`。
   - 支持快速加减按钮 + 直接输入。
5. **自定义价格（1.0新增）**
   - **所有商品均可下单时改价**：点击订单明细中的商品价格，可修改件价/包价，**仅对当前订单有效**，不影响商品默认价格，也不影响其他订单/其他客户。
   - 改价后商品明细标记 `is_price_modified=true`，记录原始价格 `original_price_*` 供对账追溯。
6. **客户下单自带上次默认价格（1.0新增）**
   - 新开订单选择客户后，商品价格**默认取该客户最近一笔订单（network_time 最近）的成交价**；该客户无历史订单时回退商品默认价。
   - 订单内改价只影响当前订单；客户上次价格以"最近成交价"为准动态推导，无需单独维护。
7. **订单操作**
   - 支持多行商品录入，自动合计。
   - **创建即入「待分拣」**（无"保存草稿"环节）；支持"复制订单（基于历史订单）"。
   - 支持"备注"字段（如到货时间、特殊要求），**下单员可随时修改订单备注**（订单任何状态下均可改，不影响订单状态）。
   - **提交订单二次确认弹窗**：「（区域-店名）的订单 数量与订单数量确认无误？」（不含订单号和金额）。
   - **提交成功提示**：「已提交，进入待分拣」。
   - **提交后一键蓝牙打印**：订单提交成功后弹窗询问「是否立即打印送货单？」。

#### 4.3.3 订单查看与管理
- **订单列表（1.0 布局改版）**：
  - **当日订单：按客户分组完整卡片展示**（每个客户一个分组，卡片内展示当日该客户的多张订单，可展开显示商品明细/金额/状态）。
  - **昨天及更早订单：折叠为单行列表**（一行显示：订单号+客户+金额+状态），点击单行进入订单详情。
  - 按时间倒序，显示客户名、金额、状态、颜色标识。
  - **订单列表 Tab（时间维度，以原型为准）**：全部 / 今日 / 本周 / 本月（分拣员默认「待分拣」，库管默认「已分拣（待出库）」）。
  - 支持按状态筛选、按客户/区域/下单员筛选。
 - **订单详情**：
   - 商品明细、金额、时间、操作人（下单员/分拣员/库管三方追溯）。**完整视图，含单价/金额，所有角色一致（精简视图与价格脱敏已取消，1.0）。**
   - **商品明细（1行/商品，1.0）**：订单详情中**每个商品只显示 1 行**；同时有件和包时，**数量列按实际合并展示**（如「2件10包」；仅件→「N件」；仅包→「N包」），单价列显示件价（含包价参考），金额为件+包实际合计。
  - **物流包裹**：已出库（confirmed）订单在**订单详情弹窗**与**订单详情页「订单信息」区**显示「物流包裹：大件X · 中件X · 小件X」（来源：库管出库确认时录入的 ship_large/ship_medium/ship_small），**所有角色可见**；未出库（待分拣/已分拣）订单物流包裹为空/0。
  - **分拣查看详情（待分拣 submitted 状态）**：
    - 完整视图，底部有【分拣备注】textarea（可填：破损/缺货/替换品），下方一个主 CTA：
      - 主色：🔍 分拣完成（写 sort_remark，状态 submitted→sorted，一键完成，`startSorting`；列表页支持【全部分拣】批量）。
  - **库管查看详情（出库确认）**：
    - 完整视图。
    - **出库确认（一步）**：底部 CTA：【确认出库】→ 状态 sorted→confirmed（`confirmOrder`；列表页支持【全部确认】批量），可同时录入实际发货件数（大件/中件/小件，写入 **ship_large / ship_medium / ship_small**）作为物流包裹展示。
- 操作：编辑订单（改后状态回退）、删除订单（二次确认）、复制订单、**蓝牙打印送货单**、**登记收款（见 4.3.7 赊销收款管理）**。
- **操作记录（1.0 新增，订单修改历史）**：订单详情页底部新增「操作记录」区块，按时间倒序展示该订单的完整操作历史（创建/编辑/删除/收款登记/收款确认/分拣/出库等），每条含操作人、角色、时间、操作内容。数据存 `order_logs` 集合，用于追溯"谁在什么时候改了什么"。

#### 4.3.7 赊销收款管理（1.0 全面升级）

- **独立入口**：底部Tab「💰赊销」页，**所有角色可见**（`receivable:view` 关闭时该 Tab 自动隐藏）；订单详情页/订单列表也可直接点【收款】（1.0 统一按钮，按角色分流登记/确认）。
- **三栏结构（核心，原型口径）**：赊销页 3 个 Tab —— **📋客户台账 / 📌未结清 / ✅已结清**，外加页面独立的 **「✅ 收款确认」按钮**（打开库管确认工作台）。
  - **📋客户台账**：以**客户为单位**显示总账三个金额 —— **应收总额 / 已收 / 未结清**，满足**金额守恒**：`应收总额 = 已收 + 未结清`。卡头为客户名 + 区域，右侧显示未结清金额与状态标签。
  - **📌未结清**：列出所有仍有欠款的订单（按客户/时间聚合），每笔一行含金额、账期/逾期天数徽标。
  - **✅已结清**：列出已全额结清的订单（灰显，含实收/确认人/确认日）。
  - **「✅ 收款确认」按钮**：库管确认工作台入口——列出**待确认**收款（已登记、按登记时间升序），库管/管理员逐笔确认；按钮带「·N 待确认」角标。
  - **金额口径统一为「已收」**：全站用 **已收（received，含部分收款/折价）** 替代原「已结清（仅完全结清）」口径；**客户台账 / 汇总 / 导出三处统一**。
  - 顶部**搜索框**（客户名/区域实时筛选）+ **账期快捷筛选**（全部 / 30天内 / 1-2月 / 2-3月 / 3月+，按最长欠款天数过滤）。
  - **最长欠款天数**：色点按逾期严重度着色（≤30天绿、1-2月黄、2-3月橙、3月+红）。
- **导出报表**：支持**周期选择（全部 / 今日 / 本周 / 本月 / 自定义）**；**明细行订单号已含时间，故不重复显示时间列**；**汇总行显示 应收 / 已收 / 未结清**三项。
- **订单收款状态机（1.0）**：
  - `unpaid` 未收款（**所有订单默认未收款**，无任何收款记录）
  - `pending` 未结清（已登记收款**尚未全额结清**：含待库管确认、或部分收款已确认但仍有剩余欠款）
  - `paid` 已结清（累计实收 + 折价/货损 ≥ 订单金额，全部还清）
- **收款流程（统一两步，1.0 收敛为单一【收款】按钮）**：
  - **统一「收款」按钮（1.0）+ 角色权责分离（1.0）**：订单详情、订单列表、赊销页（客户卡片 / 每笔订单行）均只保留**一个【收款】按钮**，按当前角色自动分流——**下单员/分拣员**点开【收款登记】金额框（填实收金额/折价/备注，默认带出剩余欠款），提交后收款**下推库管**待确认（订单 `unpaid→pending`，状态转蓝）；**库管**点【收款】只打开【确认收款】列表逐笔确认、**不登记收款（库管无登记权限）**，无待确认收款时提示「请等待下单员/分拣员登记」；**管理员**兼有两者（有待确认则确认、否则可代登记）。按钮上带「·N 待确认」笔数提示，无需再区分「登记」「确认」两个入口。
  1. **① 登记收款（权限 `receivable:collect`，下单员/分拣员/管理员可，库管不可）**：点击【收款】→ 填写**收款方式（现金/微信，用于台账"现余/微信"拆分）**、**实收金额**、**折价/货损金额（可选）**、备注 → 保存 → 订单 `unpaid→pending`，Toast「已登记收款，已下推库管确认」。**库管角色被禁止登记收款（强行提交会拦截并提示）。**
  2. **② 确认收款（权限 `receivable:confirm`，库管/管理员可，下单员/分拣员不可）**：点击【✅ 收款确认】→ 打开待确认收款列表逐笔【确认】→ 若订单**全部结清**则状态 `pending→paid`；若**仍有剩余欠款**则保持 `pending`（未结清），该笔收款计入**已收**。
  - **统一两步流程（无订单级收款方式，1.0）**；支持部分收款（一次登记部分金额，多次累计至还清）；订单剩余欠款 = 订单金额 − 累计实收 − 累计折价/货损。
  - **折价/货损（货损价）**：实收不等于应付的场合（如100元货品实际只收90元、折价10元），登记收款时可填写**折价/货损金额**，用于记录货物损耗/让利；应付 − 实收 − 折价 = 剩余欠款。
- **收款记录字段（1.0）**：收款方式（现金/微信，台账"现余/微信"拆分用）、实收金额、折价/货损金额、收款时间、登记人（下单员/分拣员）、确认人（库管）、确认时间（**订单级收款方式已取消；收款记录仅保留"现金/微信"渠道字段用于台账拆分**）。
- **说明**：本功能为**内部赊销对账管理**，不涉及任何第三方支付收款码；送货单/订单/页面**不再印制商户收款码**（1.0 取消，央行259号文合规内容下线）。

#### 4.3.9 转发客户微信（1.0 新增，与 4.3.8 取消的收款码卡片是两回事）
- **目的**：把**订单明细**推送给客户微信，供客户核对商品、数量、金额与未付款状态（不收款、不含任何收款码 / 259号文内容）。
- **入口**：①新建订单提交后**自动弹出转发层**；②订单详情页【📤 转发客户微信】按钮（任意订单可用）。
- **内容**：微信卡片按「{客户名}食品销售单」模板 = 丰淮商贸采购订单 + 客户/区域/时间 + 商品明细（名称·数量·金额）+ 合计 + **累计欠款** + 订单号；付款状态在卡片外的转发提示文案中表达（如"并确认付款"）；接收方为该客户的**微信好友**（按客户 contact/phone 定位）。
- **动作**：点【发送给客户微信】→ 标记订单 `shared_to_wechat=true` + `shared_at`，Toast「已转发至客户微信」；订单详情「微信转发」行显示已转发时间。
- **合规**：仅转发订单信息，**不绑定任何第三方支付/收款码**，与 1.0 取消的收款码卡片无关联；实际微信转发由小程序 `onShareAppMessage` / 开放标签实现（原型以弹层模拟）。

#### 4.3.10 智能录入（文字/语音快速下单，1.0 新增）

- **入口**：①首页「智能录入」卡片；②新建订单页「智能录入」按钮。
- **两种录入模式**：
  - **文字录入**：粘贴微信聊天记录或手动输入自然语言文本，支持格式如「送 2 件手抓饼给东一路刀削面」「手抓饼 2 件，老酸奶 10 包」。
  - **语音录入**：点击麦克风按钮录音，语音转文字识别（生产化阶段对接腾讯云 ASR，按量计费，有免费额度，以控制台为准）。
- **智能解析**：点击「智能解析」按钮，系统自动从文本中识别商品名称、数量、客户名称。
- **匹配规则**：
  - 严格匹配库中已有商品和客户，**不允许生成库中不存在的内容**。
  - 支持模糊匹配（Levenshtein 距离，阈值 0.6）、别名匹配、拼音首字母匹配、包含匹配。
  - 匹配到多个结果时，弹出选择列表让下单员选择。
- **智能记忆**：下单员选择后，系统记忆该输入文本对应的选择结果（`productLastUsed` / `customerLastUsed`），下次输入相同文本时自动使用上次选择，无需再次选择。
- **解析结果预览**：生成订单草稿预览（客户+商品明细），下单员确认后可编辑/调整再生成订单。
- **未匹配处理**：无法匹配的商品/客户标红提示，下单员需手动从库中选择或取消该项。
- **AI 服务依赖（1.0 新增，管理员在「系统设置」配置）**：
  - **语音转文字**：依赖腾讯云语音识别（录音文件识别），需配置 SecretId / SecretKey / 识别引擎（16K/8K），并启用开关。
  - **复杂语义理解（NLP 兜底）**：规则引擎未命中时可选接入通义千问（DashScope），需配置 API Key / 模型，并启用开关。
  - **降级策略**：未配置或未启用任一 AI 服务时，智能录入自动降级为纯规则引擎（文字匹配仍可用），不影响核心下单流程。
  - **密钥安全**：AI 密钥仅存云端 `system_config` 集合，由管理员在「系统设置」配置，不写入前端代码，不泄露到客户端。

  - **2026-08-17 服务端双重校验**：云函数 `orders` 的 `create`/`update` 除校验 `totalAmount > 0` 外，还**按物品行重算金额合计**——有效商品行（件数+包数均 0 的行先过滤）为空、或物品金额合计 ≤ 0（物品行未带金额/单价为 0）时同样拦截不生成，防止 `totalAmount>0` 但物品金额为 0 的脏数据入库。
- **列表过滤**：订单列表、赊销看板、报表汇总等**所有列表均过滤 0 元订单**，不计入统计。
- **0件0个隐藏**：已成订单中，`piece_qty = 0` 且 `package_qty = 0` 的商品行**不显示**（列表、详情、打印/转发销售单一致）。

- **实现位置**：云函数 `orders`（create/update 双重校验、exportOutbound/exportSingleOrder 0 值留空）+ 云函数 `report`（台账/客户汇总导出 0 值留空）；前端 `utils/order-pricing.formatQtyCombined`、订单列表/详情/出库页同步 0 值隐藏。

### 6.2 订单状态机（简化后：一键分拣 + 一步出库）

```
 新建订单即入：待分拣(SUBMITTED) ──【分拣完成 / 全部分拣】──→ 已分拣(SORTED)
                                        startSorting                │
                                                                    │【确认出库 / 全部确认】confirmOrder
                                                                    ▼
                                                            已出库(CONFIRMED) → 已完成(COMPLETED)
```

**主线**：`新建即入待分拣(submitted) → 已分拣(sorted) → 已出库(confirmed) → 已完成(completed)`

- **分拣**：一键「待分拣 → 已分拣」（`startSorting` / 全部分拣），无「分拣中」中间态。
- **出库**：库管一步确认「待出库(已分拣) → 已出库」（`confirmOrder` / 全部确认）。
- 原「确认发货 / 分拣中(checked) / 已驳回(rejected)」中间态**已取消**；无"保存草稿"、无"手动取消"动作。
- `draft(DRAFT)`、`cancelled(CANCELLED)`、`rejected(REJECTED)` 状态**保留定义但当前流程不触发**（无草稿创建/取消入口；驳回为遗留/二期，见 §4.7 二期规划，不纳入主流程）。

**状态颜色方案**：
- 草稿(DRAFT)：灰色 #909399
- 待分拣(SUBMITTED)：橙色 #E6A23C → **等待分拣处理**
- 已分拣(SORTED)：蓝色 #409EFF → **已分拣完成，待库管出库确认**
- 已出库(CONFIRMED)：紫色 #722ED1 → **库管已确认出库，待司机拉货**
- 已完成(COMPLETED)：深绿 #008000
- 已取消(CANCELLED)：深灰 #909399
- ~~已驳回(REJECTED)：红色 #F56C6C~~：遗留态，当前流程不触发（见 §4.7）

**SLA 超时自动处理（已实现）**：**管理员在设置页统一控制「定时自动确认」——开关 + 时间选择（默认关闭，默认 16:00）；开启后每天到点，仍未确认的分拣/出库订单全部自动确认（每日一次），分拣员与库管工作台显示定时提示并标红超时订单；关闭则不限时、不显示任何定时提示，需人工确认**；原型保留「⏰模拟到点通过」按钮；日常分拣与出库仍由人工一键/一步完成。

### 6.3 关键约束
- 订单号全局唯一，规则：前缀 `丰淮商贸-` + `YYYYMMDD + 4 位序号`（如 丰淮商贸-20260803-0001，可根据客户要求隐藏前缀）。
- 同一订单明细商品 SKU 唯一。
- 快照在"提交订单"时生成并不可变。
- **全员可下单/改单/删单（1.0）**：下单员/分拣员/库管/管理员 4 角色均可新建、修改、删除订单（含订单内改价）；分拣员只读与库管价格脱敏规则已取消。
- **订单内自定义价格（1.0）**：所有商品下单时均可改价，仅对当前订单有效，不影响商品默认价与其他订单；改价明细标记 is_price_modified + original_price_*。
- **客户上次价格（1.0）**：新开订单商品价格默认取该客户最近订单成交价，无历史则用商品默认价。
- **串行简化流程**：提交后订单进入**待分拣**，分拣一键完成后进入**已分拣（待出库）**，库管一步确认后进入**已出库**；无并行配货/暂存态，无驳回回退（见 §4.7 二期规划）。
- **首管理员（方案 A 零配置）**：系统首次启动、无任何管理员时，第一位登录者由 login 云函数自动赋 `role=admin`；**无需环境变量或预置 openid**。
- 所有操作人（下单员/分拣员/库管）均要写 `*_by + *_at` 字段，保证打印送货单和对账时三方追溯。
- **赊销金额守恒**：客户台账满足 `应收总额 = 已收 + 未结清`；「已收」含部分收款与折价/货损，台账/汇总/导出三处口径一致。

### 7.3 关键交互细节
- **件包联动**：件数变化时自动换算包数（可手动覆盖）；包数变化反向扣减件数。
- **数量默认 0**：添加商品时件数/包数默认 0，输入框加大，支持快速加减 + 直接输入。
- **实时合计**：每加/减商品即刻更新合计金额。
- **防误触**：删除订单需二次确认 + 输入订单号后 4 位。
- **操作反馈**：保存/提交成功 Toast，失败带错误原因。
- **分拣流程（待分拣 → 已分拣，一键完成）**：
  - 在「🔍分拣出库」页分拣段点「待分拣」订单卡片 → 弹全屏详情（**完整视图**；商品数量/价格按全员权限可编辑）
  - 底部【分拣备注】textarea，提供快捷短语按钮（"全部完好"、"A缺货2件"、"B破损1件"、"替换C品"）→ 点击直接填充，减少打字
  - 主 CTA：🔍 **分拣完成**（`startSorting`，点后弹确认「确认订单 XXX 分拣完成？将进入待出库」→ 状态 submitted→sorted）
  - 列表页提供【全部分拣】批量按钮，一键把当前「待分拣」列表全部置为已分拣
- **出库流程（待出库(已分拣) → 已出库，库管一步确认）**：
  - 库管在「🔍分拣出库」页出库段点「待出库」订单卡片 → 详情弹窗（**完整视图**；商品明细可编辑、价格可见）+ 分拣备注灰色显示
  - 底部 CTA：【**确认出库**】（`confirmOrder`）→ 状态 sorted→confirmed，紫色「已出库」；可同时录入实际发货件数（大件/中件/小件，写入 ship_large/ship_medium/ship_small）
  - 列表页提供【全部确认】批量按钮；「已出库」列表卡片与订单详情显示「物流包裹：大件X · 中件X · 小件X」
- **赊销收款流程（登记 → 确认两步）**：
  - **① 登记收款**（`receivable:collect`，下单员/分拣员/管理员，库管不可）：在订单详情或赊销页点【收款】→ 填**收款方式（现金/微信）**、**实收金额、折价/货损金额（可选）**、备注 → 订单「未收款」→「待确认」，下推库管，Toast「已登记收款，已下推库管确认」
  - **② 确认收款**（`receivable:confirm`，库管/管理员，下单员/分拣员不可）：点赊销页独立【✅ 收款确认】按钮 → 待确认列表逐笔确认 → 该笔计入**已收**，全额结清则订单转「已收款」，Toast「收款已确认」
  - 赊销页三栏实时联动：**📋客户台账**（应收总额 / 已收 / 未结清，金额守恒）、**📌未结清**、**✅已结清**；欠款为 0 的客户在「未结清」栏自动不显示
- **系统提醒（showConfirm / Toast）**：
  - 下单员提交前 showConfirm 二次确认：「**（区域-店名）的订单 数量与订单数量确认无误？**」（不含订单号和金额）
  - 下单员提交成功后 Toast：「**已提交，进入待分拣**」
  - 分拣完成后 Toast：「已分拣完成，今日已分拣X笔 / 待出库X笔」
  - 库管【确认出库】成功后 Toast：「已确认出库」
  - 库管登录/进入「分拣出库」页时，若今日有已分拣待出库订单 → Toast「今日 X 笔订单等待出库」
- **蓝牙打印流程**：提交订单 → 弹窗「是否打印送货单？」→ 是 → 自动连接默认打印机 → 打印中动画 → 完成提示。

## 12. 验收标准

1. **功能验收**：核心流程（**录单→提交（待分拣）→一键【分拣完成/全部分拣】（已分拣）→库管一步【确认出库/全部确认】（已出库）→已完成→**3种Excel导出 + 蓝牙打印送货单（含三方追溯 + 收款状态））100% 通过。
2. **数据验收**：167 商品 + 120 客户初始化数据完整导入；users表含 admin + 2orderer + 1sorter + 1warehouse 共5角色；orders表覆盖简化状态机各态至少2笔样例（草稿 / 待分拣 / 已分拣 / 已出库 / 已完成 / 已取消）；products表 usage 字段正常累计；收款记录 Payment 至少2笔样例（含 pending 待确认 与 confirmed 已确认 各 1 笔，其中 1 笔含折价/货损 discount）。
3. **商品选择交互验收（本轮需求）**：录单页选商品弹窗**默认仅罗列 3-4 行（4 个）常购/高频商品**；**输入搜索词后展示全部匹配商品**（"通过搜索商品来获取列表"）。
4. **商品排序与 usage 累计验收（本轮需求）**：选商品排序**先按固定商家（客户）维度常购次数降序优先**（该客户历史订单中购买越多的商品越靠前），**其次按全局使用频率 products.usage 降序**；**每成功新建一单，订单内商品 usage +1**。
5. **权限验收**：**下单员/分拣员/库管/管理员** 4角色权限完全符合4.2矩阵（重点核对：**4角色均可新建/修改/删除订单（含订单内改价），无价格脱敏与只读限制**；`sort:task` / `warehouse:confirm` 默认全员开放，管理员在「成员管理 → 权限配置」关闭后对应 Tab 运行时自动隐藏；`receivable:collect` 库管不可、`receivable:confirm` 下单员/分拣员不可）。
6. **蓝牙打印验收**：芯烨XP-58IIH（58mm）现场打印送货单，中文不乱码、格式正确、二维码可扫；**送货单按「{客户名}食品销售单」模板原样打印（客户信息 + 商品明细 + 合计 + 累计欠款 + 制单人 + 签收栏），不包含三方操作人追溯 / 分拣备注 / 收款状态 / 物流件型（客户端指定格式）**；**不含任何商户收款码（1.0下线）**；**商品明细同商品件+包合并1行、无规格列、数量字体加大**。
7. **底部 Tab 验收**：底部共 **5 个 Tab**——📋首页 / 📦订单 / 💰赊销 / 🔍分拣出库 / 👤我的（符合微信 tabBar 硬上限）；「分拣出库」页内含分拣段（待分拣/已分拣）与出库段（待出库/已出库）两段切换；报表入口在「我的 → 报表统计」，不单独占 Tab。
8. **状态机验收**：主线 **新建即入待分拣(submitted) → 已分拣(sorted) → 已出库(confirmed) → 已完成(completed)** 全链路可走通；无"保存草稿"、无"手动取消"动作；**无「确认发货 / 分拣中 / 已驳回」中间态**（`draft`/`cancelled`/`rejected` 为遗留定义，当前流程不触发）。
9. **首管理员零配置验收（方案 A）**：全新环境无任何管理员时，**第一位登录者自动成为 `role=admin`**（login 云函数赋值），全程**未配置任何环境变量、未预置 openid**；第二位及以后登录者不再自动提权。
10. **导出验收**：客户汇总表（外县台账式）列顺序/字段/分组与业务方提供Excel完全一致，可直接复制粘贴。
11. **非功能验收**：满足第5章指标。
12. **赊销收款管理验收**：底部Tab「赊销」为**三栏 📋客户台账 / 📌未结清 / ✅已结清 + 独立「✅ 收款确认」按钮**；客户台账以客户为单位显示 **应收总额 / 已收 / 未结清**，且满足**金额守恒 应收 = 已收 + 未结清**；台账/汇总/导出三处统一使用「已收」口径（含部分收款/折价）；订单默认「未收款」且无收款方式字段（1.0）；登记收款（`receivable:collect`）后订单变「待确认」，确认收款（`receivable:confirm`）后计入已收；支持部分收款累计；导出报表支持周期选择（全部/今日/本周/本月/自定义），明细行不重复显示时间列，汇总行显示 应收/已收/未结清；**订单/送货单/页面均无商户收款码与259号文内容**。
13. **物流包裹验收（需求#12新增）**：库管【确认出库】时录入的实际发货件数写入 **ship_large / ship_medium / ship_small**；「分拣出库」页出库段「已出库」列表卡片、**订单详情弹窗 + 订单详情页「订单信息」区**（已出库订单，所有角色可见）均显示「物流包裹：大件X · 中件X · 小件X」；**导出主报表（导出报表Excel）与出库单Excel** 含「发货大件 / 发货中件 / 发货小件」3 列、**单订单送货单**信息区含物流包裹行；**未出库（待分拣/已分拣）订单物流包裹为空/0**；**客户汇总表（外县台账式）保持 1:1 台账格式不变**。
14. **自定义价格验收（1.0新增）**：订单内可修改任意商品件价/包价，仅对当前订单生效；不影响商品默认价与其他订单/客户；改价明细记录 is_price_modified + original_price_*。
15. **客户上次价格验收（1.0新增）**：选择客户后新开订单，商品价格默认取该客户最近订单成交价；无历史订单客户用商品默认价。
16. **订单列表布局验收（1.0新增）**：当日订单按客户分组完整卡片展示；昨天及更早订单折叠为单行列表（订单号+客户+金额+状态）。
17. **收款码下线验收（1.0新增）**：全端（订单页/送货单/导出/任何卡片）检索不到商户收款码、经营码、259号文相关内容。
18. **商品明细1行+默认数量验收（本轮新增）**：订单详情页/送货单**每个商品只显示 1 行**，数量列按实际合并展示（同商品有件有包→「N件M包」；仅件→「N件」；仅包→「N包」），单价列显示件价（含包价），金额为件+包实际合计；**新建订单添加商品时数量默认 0（非 1）**，由用户按实际填写。
19. **智能录入验收（1.0新增）**：首页智能录入卡片+新建订单页按钮可用；文字录入支持粘贴/手动输入自然语言文本；语音录入支持录音转文字；智能解析能正确识别商品名称、数量、客户；严格匹配库中已有数据，不生成不存在的内容；模糊匹配阈值 0.6，简称/缩写可匹配；多结果时弹出选择列表；智能记忆功能正常（上次选择自动复用）。

## 13. 附录

### 13.1 术语表
- SKU：商品唯一编码。
- 件价/包价：整件价与包价（默认单位"包"，如 1 件 = 24 包，件价 120 元，包价 5 元/包）。
- 送货单：交付客户的签收凭证，含价格。
- 出库单：库管备货用单据，不含价格。
- ~~商户收款码/经营码~~：原「商户收款码收款 + 央行259号文合规」内容已于 **1.0 整体下线**，收款改为内部赊销对账（登记→库管确认）。
- 收款状态：未收款(unpaid) / 待确认(pending，已登记待库管确认) / 已收款(paid)。
- ESC/POS：热敏打印机通用指令集标准，由爱普生制定，99%热敏打印机兼容。
- 58mm/80mm：热敏打印纸宽度规格，58mm为小票常用，80mm字更清晰。
- 智能录入：通过文字粘贴/语音输入自然语言，系统自动解析商品、数量、客户信息并匹配库中数据的快速下单方式。
- 模糊匹配：基于 Levenshtein 距离算法，允许输入与库中名称存在一定差异（阈值 0.6）仍能匹配成功。
- 智能记忆：系统记忆下单员对同一输入文本的历史选择，下次自动复用，减少重复选择。

### 13.3 用户交互
1. 进入「我的」页面
2. 点击「主题设置」入口
3. 在主题选择页面点击任意主题卡片
4. 主题立即生效并保存到本地缓存
5. 重启小程序后保持上次选择的主题

### 13.4 技术实现
- 使用 CSS 变量实现动态主题切换
- 主题配置保存在 `utils/theme-helper.js`
- 导航栏颜色随主题自动调整
- 所有页面统一应用主题样式
- 主题切换回调通过 `onThemeChange` 通知各页面

### 13.5 权限说明
- **所有角色**：均可访问主题设置功能
- **管理员专属**：系统设置中的语音配置、千问配置、打印机配置等
