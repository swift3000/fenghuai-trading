# 丰淮商贸采购下单助手 — 开发检查清单 (Checklist)

> **用法**：每个阶段、每次提交前，对照本清单逐项打勾。全部通过再进入下一步。
> **配套**：[开发规范.md](./开发规范.md) · [代码规范.md](./代码规范.md) · [Git协作规范.md](./Git协作规范.md)

---

## 一、需求阶段 Checklist

开始一个新功能前：

- [ ] 能一句话说清：给谁用、解决什么问题、怎么算成功
- [ ] 原型已画完，交互流程走通
- [ ] 边界情况已列出（空数据、断网、超长输入、重复提交）
- [ ] 需求已编号（如 `REQ-订单-001`）
- [ ] 业务方已确认（口头/截图/签字都行）

---

## 二、设计阶段 Checklist

写代码前：

- [ ] 涉及的集合/字段已在 ERD 中确认或补充
- [ ] 涉及的接口已在 API 文档中定义（入参/出参/错误码）
- [ ] 复杂逻辑已画流程图或写伪代码
- [ ] 是否影响已有功能已评估
- [ ] 方案比选过「简单 vs 完整」，优先简单

---

## 三、开发前 Checklist

新建模块/功能前：

- [ ] 目录结构符合 [开发规范.md §4.1](./开发规范.md)
- [ ] `.gitignore` 已配置（`node_modules/`、`.env`、`.DS_Store`）
- [ ] 环境变量走 `config/`，无硬编码密钥
- [ ] 依赖已记录在 `package.json`，未提交 `node_modules/`

---

## 四、编码 Checklist（每次写完代码自查）

### 4.1 命名
- [ ] 变量/函数 camelCase（`orderList`、`submitOrder`）
- [ ] 常量 UPPER_SNAKE_CASE（`MAX_PAGE_SIZE`）
- [ ] 组件 PascalCase（`OrderCard.vue`）
- [ ] Vue 响应式变量带 `Ref` 后缀（`orderListRef`）
- [ ] 布尔变量 `is/has/can/should` 开头
- [ ] 见名知意，无 `temp`/`data`/`info`/`a`/`b` 等无意义名

### 4.2 代码风格
- [ ] 2 空格缩进
- [ ] 无行尾分号（Vue/JS）
- [ ] 单引号优先，字符串用模板字符串
- [ ] 用 `===`/`!==`，无 `==`/`!=`
- [ ] 用 `const`/`let`，无 `var`
- [ ] 单文件不超过 300 行（超了考虑拆分）

### 4.3 Vue 规范（Web 后台）
- [ ] 用 `<script setup>` + Composition API
- [ ] 未使用 Options API（`data()`/`methods`）
- [ ] props 用 `defineProps` + 类型声明
- [ ] 样式有 `scoped`

### 4.4 小程序规范
- [ ] 页面 4 文件齐全（js/wxml/wxss/json）
- [ ] `setData` 合并调用，无大对象
- [ ] 云函数调用走 `services/` 封装

### 4.5 云函数规范
- [ ] 用 action 路由模式
- [ ] 返回 `{ code, data, message }` 三段式
- [ ] 查询有 `limit`
- [ ] 写操作有入参校验
- [ ] 删除用软删除（`isDeleted: true`）
- [ ] 权限在云函数内校验，不信任前端角色

### 4.6 请求与错误处理
- [ ] 请求走 `request.js`/`services`，无裸 `fetch`/`axios`
- [ ] 所有异步有 `try/catch` 或 `.catch()`
- [ ] 错误码按约定处理（401 跳登录、500 提示重试）

### 4.7 注释
- [ ] 文件头有 1 行作用说明
- [ ] 复杂函数有 JSDoc（参数/返回值）
- [ ] 业务规则有注释（标注 PRD 编号）
- [ ] 无废话注释（`// 设为 0` 这种）

### 4.8 安全
- [ ] 无硬编码密钥/AppID/环境ID
- [ ] 用户输入已校验（长度/类型/特殊字符）
- [ ] 日志不打印密码/手机号明文（脱敏）
- [ ] 敏感操作有二次确认

### 4.9 性能
- [ ] 列表有分页（默认 20/页）
- [ ] 图片用缩略图
- [ ] 搜索/提交按钮有防抖
- [ ] 无循环里查数据库（N+1）

---

## 五、测试 Checklist

- [ ] 本地能跑起来，无控制台报错
- [ ] 核心流程手动点过一遍（真实数据）
- [ ] 异常场景测过：空数据、断网、超长输入、重复提交
- [ ] 权限边界测过：下单员不能看管理员数据
- [ ] 测试用例已记录（TC-模块-编号）
- [ ] 发现的 bug 已记录到《缺陷记录.md》

---

## 六、提交前 Checklist（Git）

- [ ] `git status` 看过，没有误加的文件
- [ ] 没有提交 `.env` / `node_modules/` / 密钥
- [ ] 提交信息符合规范（`类型: 描述`）
- [ ] 一次提交一件事，没堆多个无关改动
- [ ] 提交后 `git log` 确认信息无误
- [ ] （如需）已 `git push origin dev`

---

## 七、发布前 Checklist

- [ ] dev 分支核心流程通过
- [ ] 数据库已备份
- [ ] 版本号已确定（如 v0.1.0）
- [ ] 云函数已部署
- [ ] 小程序已提审 / Web 后台已发布
- [ ] 已打 tag（`git tag -a v0.1.0 -m "..."`）
- [ ] 已合并到 main 并推送
- [ ] 线上冒烟测试通过（登录→下单→审核→打印→导出）
- [ ] 有回滚方案（保留上一版本代码）

---

## 八、运维 Checklist（每周/每月）

- [ ] 查看云函数错误日志
- [ ] 数据库手动备份一次
- [ ] 检查集合大小、慢查询
- [ ] 离职账号是否已禁用
- [ ] 本周问题已复盘记录
- [ ] 下周计划已列出

---

## 速查：一句话规范

| 维度 | 一句话 |
|------|--------|
| 心态 | 先想后做，小步快跑，能跑才算数 |
| 命名 | 见名知意，驼峰常量大写 |
| 风格 | 无分号、用 ===、用 const、用模板字符串 |
| Vue | script setup + Composition API + scoped |
| 请求 | 统一封装，禁止裸 fetch |
| 错误 | 异步必有 try/catch |
| 安全 | 密钥进环境变量，删除用软删除 |
| Git | 一次一事，规范提交信息 |
| 测试 | 真实数据跑一遍，不只看不报错 |
| 发布 | 备份 + 打 tag + 冒烟 + 回滚方案 |
