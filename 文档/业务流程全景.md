# 丰淮商贸采购下单助手 · 业务流程全景

> 版本：1.0 ｜ 配套：PRD / TDD / ERD / API / 用户操作手册 ｜ 状态：主干流程已落地

> 本文档已按 MVP（v1.0，2026-08-05）口径修订，MVP 为最终功能范围，无二期增强；功能清单与范围以《小程序 MVP 落地计划与技术架构》为准。

本文档是产品**端到端业务流程的单一事实来源**。每条流程标注：角色、入口、前置条件、主步骤、异常/边界、状态变化、**是否已落地**。

图例：✅ 已落地 ｜ 🟡 部分落地 ｜ ⏭️ MVP 不含（后续独立升级模块）

## 0. 全链路总览

```
        录单(下单员/分拣员)                  分拣(分拣员)              出库(库管)
   ┌─────────────────────┐  ┌──────────────────┐  ┌──────────────────────┐
   │ 选客户→带出上次订单 │→│ 待分拣→已分拣     │→│ 待出库→已出库         │
   └─────────┬───────────┘  └────────┬─────────┘  └──────────┬───────────┘
             │                       │                        │
             └───────────────────────┴────────┬───────────────┘
                                               ↓
                                   打印送货单(蓝牙) / 转发客户微信
                                               ↓
                          赊销收款闭环：登记(下单员/分拣员)→确认(库管)→结清
                                               ↓
                                  报表汇总 / Excel 导出（对账 MVP 不含）
```

订单状态机（独立维度，见 README）：
`草稿 → 待分拣(submitted) → 已分拣(sorted) → 已出库(confirmed) → 已完成(completed)`；可 `已取消(cancelled)`。
收款状态机（独立维度）：`未收款(unpaid) → 登记待确认(pending) → 已收款(paid)`。

## 1. 录单流程 ✅

| 项 | 内容 |
|----|------|
| 角色 | 下单员、分拣员（均可录单/改单/删单） |
| 入口 | 底部 Tab「订单」→ 新建订单 |
| 前置 | 已登录、客户/商品基础数据存在 |
| 主步骤 | ① 选客户 → **自动带出该客户上次订单的商品与数量**（标「预填」，可改/删）<br>② 点「+ 添加商品」选品（无搜索词仅列前 3 常购，搜索后全列）<br>③ 订单内可改价（仅当前订单，客户自带上次成交价）<br>④ 件+包双轨，单位统一"包"<br>⑤ 提交 → 状态置「待分拣」 |
| 异常/边界 | 编辑已有订单（state.currentOrderId 存在）不触发自动带出；客户无历史订单则不预填<br>**0 元订单拦截（MVP）**：新建/编辑提交时若订单金额为 0，直接拦截不生成订单并提示 |
| 状态变化 | 草稿 → 待分拣 |
| 落地 | ✅ 原型已落地；"一键复制上次订单"原入口随右栏移除被删，**入口待重新设计**（PRD 已标注） |

| 状态变化 | 待分拣 → 已分拣 |
| 落地 | ✅ 原型已落地 |

## 3. 库管配货流程 ✅

| 项 | 内容 |
|----|------|
| 角色 | 库管（管理员可代） |
| 入口 | 底部 Tab「分拣出库」工作台（出库段） |
| 前置 | 订单状态 = 已分拣（待出库） |
| 主步骤 | ① 查看待出库订单（已分拣）<br>② 库管一步确认「待出库 → 已出库」（`confirmOrder` / 全部确认）→ 后续「已完成」 |
| 异常/边界 | 简化模型：出库为库管一步确认，无暂存配货 / 超时自动（件型为出库确认已实现功能；16:00 出库超时自动定时为二期，原型保留「⏰模拟16:00通过」手动按钮；详见 §8） |
| 状态变化 | 已分拣（待出库） → 已出库 → 已完成 |
| 落地 | ✅ 原型已落地（红框区已去标题、放宽至 54% 留给商品+件数） |

## 4. 赊销收款闭环 ✅（缺"催"）

| 项 | 内容 |
|----|------|
| 角色 | **登记**：下单员、分拣员 ｜ **确认**：库管、管理员 ｜ 管理员两者皆可 |
| 入口 | 底部 Tab「赊销」 |
| 前置 | 订单存在且未全额收款 |
| 主步骤（登记） | ① 下单员/分拣员点【收款】→ 开「收款登记」弹窗，录入金额+备注<br>② 提交 → 收款记录 `status=pending`，**下推库管待确认**<br>③ 支持一笔订单**多次部分收款直至结清** |
| 主步骤（确认） | ④ 库管点【收款】→ 仅当有 pending 时开「确认收款」列表逐笔确认<br>⑤ 确认后收款记录 `status=confirmed`，订单 `payment_status=paid`（结清时） |
| 赊销三视图 | **客户台账**（以客户为单位显示总账：应收总额 / 已收 / 未结清，金额守恒：应收 = 已收 + 未结清）/ **未结清** / **已结清**，外加独立「✅ 收款确认」按钮（上半待确认、下半已结清灰显） |
| 异常/边界 | 库管**不能登记收款**（仅确认），违例拦截并提示；非库管在「收款确认」按钮不可触发确认操作 |
| 状态变化 | unpaid → pending → paid |
| 落地 | ✅ "看 + 登记 + 确认"已闭环 |
| ⏭️ MVP 不含 | **催收闭环**（逾期自动提醒、催收记录、坏账标记）：MVP 不含，后续作为独立升级模块按需追加（机制见《小程序 MVP 落地计划与技术架构》§7 升级机制） |

## 5. 转发客户微信 ✅

| 项 | 内容 |
|----|------|
| 角色 | 全员（任意订单可用） |
| 入口 | 订单详情【📤 转发客户微信】；新建订单提交后**自动弹出**转发层 |
| 前置 | 订单已存在 |
| 主步骤 | 生成绿色微信订单卡片（客户/区域/时间 + 商品明细 + 合计 + 未付款状态 + 订单号）→ 转发客户微信好友 |
| 异常/边界 | **不含任何收款码**（与已取消的收款码卡片是两回事，合规规避 259 号文） |
| 状态变化 | 标记 `shared_to_wechat=true` + `shared_at` |
| 落地 | ✅ 原型已落地；真实微信转发待对接微信开放能力 |

## 6. 打印与导出 ✅

| 项 | 内容 |
|----|------|
| 角色 | 全员 |
| 入口 | 订单详情【打印】/ 导出中心 |
| 主步骤 | ① 蓝牙 ESC/POS 打印送货单（**按客户指定的「西安迈尚食品销售单」模板原样打印**：客户信息 + 商品明细表 + 合计大写/小写 + 累计欠款 + 制单人 + 签收栏；**不叠加三方操作人追溯/分拣备注/收款状态/物流件型**）<br>② 导出 3 种：主报表、出库单、客户汇总表（外县台账 1:1） |
| **销售单模板（MVP）** | 打印与微信转发**统一使用「西安迈尚食品销售单」模板**：去掉 NO. 前缀；制单人电话自动取当前登录人；金额列后设**独立备注列** |
| 异常/边界 | 打印机型适配芯烨/佳博/汉印 58/80mm，需真机实测 |
| 落地 | ✅ 原型模拟打印 + CSV 导出已落地 |

## 8. MVP 不含的流程（后续独立升级模块）

> 以下流程 **MVP 不含**，后续作为独立升级模块按需追加（机制见《小程序 MVP 落地计划与技术架构》§7 升级机制）。原叙述中的"待客户确认/规划中"口径已作废。

| 流程 | 说明 | 归属 |
|------|------|------|
| 催收闭环 | 逾期提醒（微信订阅消息）、催收记录、坏账标记 | ⏭️ 独立升级模块 |
| 审计日志 | 改单/删单/收款确认操作留痕 | ⏭️ 独立升级模块 |
| 趋势报表增强 | 毛利核算、收款对账、趋势图、驾驶舱 | ⏭️ 独立升级模块 |
| 对账中心 | 收款与订单对账、银行流水 | ⏭️ 独立升级模块 |
| 客户自助下单 | 反向流程，客户自己下单 | ⏭️ 独立升级模块 |
| 分拣驳回（必填原因） | 原分拣可驳回订单、下单员改重提；`rejected` 状态保留定义但主流程不触发 | ⏭️ MVP 已取消（二期规划） |
| 暂存配货（pick_*） | 并行配货暂存、配完录实际发货件数 | ⏭️ MVP 已取消（二期规划） |
| 物流件型（大件/中件/小件） | 出库确认时填写发货件数 `ship_*` | ✅ MVP 已实现（详情/出库列表/报表/出库单展示「物流包裹」） |
| 超时自动确认 | 14:00 分拣超时自动确认发货（保持二期）；16:00 出库超时自动定时为二期规划（自动未实现），但原型保留「⏰模拟16:00通过」手动演示按钮 | ⏭️ 14:00 二期；16:00 自动二期·原型有手动模拟 |

> 注：**后端底座（微信云开发）已纳入 MVP**，为 MVP 的既定技术架构，不再属于待确认项。
