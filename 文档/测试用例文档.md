## 1. 测试策略

### 1.1 测试层级

```
单元测试（云函数）→ 集成测试（前后端联调）→ E2E测试（完整流程）→ 验收测试
```

| 层级 | 范围 | 执行方式 | 通过标准 |
|------|------|----------|----------|
| **单元测试** | 10 个云函数的每个 action | 微信开发者工具本地调试 + 云开发测试环境 | 全部用例 100% 通过 |
| **集成测试** | 前端页面 ↔ 云函数联调 | 微信开发者工具模拟器 + 真机调试 | 核心流程无阻断 |
| **E2E 测试** | 完整业务链路（录单→分拣→出库→收款→打印） | 真机多角色切换 | 5 条 E2E 流程全部通过 |
| **验收测试** | 13 项 MVP 功能 + 非功能指标 | 业务方参与，真机环境 | 验收标准 19 条全部达标 |

### 1.2 测试工具

| 工具 | 用途 |
|------|------|
| 微信开发者工具模拟器 | 云函数单元测试、前端页面功能测试 |
| 真机调试（iOS + Android） | E2E 测试、兼容性测试、蓝牙打印测试 |
| 云开发控制台 | 云函数日志查看、数据库数据校验、监控指标 |
| 微信开发者工具性能面板 | 首屏加载时间、渲染性能 |

### 1.3 测试环境

| 环境 | 说明 |
|------|------|
| 云开发环境 | 云开发测试环境（免费），与生产环境隔离 |
| 数据库 | 独立测试集合，使用种子数据初始化 |
| 小程序 | 开发版 / 体验版 |

### 1.4 测试数据

- 使用种子数据 `_DEFAULT_PRODUCTS`（167 商品）与 `_DEFAULT_CUSTOMERS`（120 客户）初始化
- 预置 11 个区域（regions）
- 预置 5 个测试用户（1 admin + 2 orderer + 1 sorter + 1 warehouse）
- 预置 28 个样例订单（覆盖各状态）
- 预置 2 笔样例收款记录（1 pending + 1 confirmed，含 1 笔折价/货损）

### 1.5 优先级定义

| 优先级 | 含义 | 发布要求 |
|--------|------|----------|
| **P0** | 核心流程，必须通过 | 发布前 100% 通过 |
| **P1** | 重要功能，影响体验 | 发布前 95% 通过 |
| **P2** | 一般功能，可延后修复 | 发布前 90% 通过 |
