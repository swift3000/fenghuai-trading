## 1. 系统概述与极简原则

### 1.1 系统组成

本系统为**小程序 + 云开发（Serverless）**架构，**无任何 Web 后台页面**：

| 模块 | 载体 | 形式 |
|------|------|------|
| 小程序端 | 微信 App | 微信原生小程序代码包（全员 4 角色使用） |
| 后端服务 | 微信云开发（CloudBase） | 8 个云函数（25 个接口）+ 7 个数据库集合 + 云存储 |

### 1.2 极简部署原则

**全部 Serverless，零服务器运维**：
- ❌ 无 Linux 服务器购买/续费
- ❌ 无 Docker、无 Nginx、无自建 API 服务
- ❌ 无 Web 后台部署（1.0 无后台页面）
- ❌ 无 CI/CD 流水线
- ✅ 一次完整部署约 1 小时

## 3. 后端部署：云开发（云函数 + 数据库）

### 3.1 初始化云开发环境

1. 打开「微信开发者工具」。
2. 导入项目：项目目录指向小程序根目录，AppID 填 2.1 #1。
3. 点顶部工具栏「☁ 云开发」→ 弹出云开发控制台。
4. 第一次会引导创建环境，命名 `fenghuai-prod`，计费方式选 **按量付费**。
5. 等待环境初始化 1-3 分钟，直到状态为可用。
6. 复制环境 ID（形如 `fenghuai-prod-3gxxxxx`）→ 填到 2.2 表格。

### 3.2 数据库：创建 7 个集合 + 索引

在云开发控制台 → 数据库 → 集合列表，依次创建以下 7 个集合：

| 序号 | 集合名 | 说明 |
|------|--------|------|
| 1 | `users` | 用户（含 4 角色） |
| 2 | `regions` | 区域（业务自定义） |
| 3 | `products` | 商品（含 usage 使用频率） |
| 4 | `customers` | 客户 |
| 5 | `orders` | 订单（含 items_snapshot 快照 + 收款状态） |
| 6 | `order_items` | 订单明细 |
| 7 | `payments` | **收款记录（1.0，登记→确认两步）** |

**关键索引清单**（建完集合后添加）：

- **users**：`username`(唯一)、`wx_openid`(唯一)、`role`、`status`
- **products**：`sku_code`(唯一)、`name`、`pricing_mode`、`usage`
- **customers**：`region_id`、`name`、`phone`、`status`
- **orders**：`order_no`(唯一)、`customer_id`、`status`、`network_time`(降序)、`created_by`、`payment_status`、组合索引 `(network_time, status)`
- **order_items**：`order_id`、`product_id`、`sku_code`、组合索引 `(order_id, seq)`
- **payments**：`order_id`、`customer_id`、`status`(pending/confirmed)、`registered_at`

### 3.4 云函数：8 个函数逐一上传

> 📌 目录结构：小程序 `cloudfunctions/` 下每个子目录 = 1 个云函数（`index.js` + `package.json`）。

依次右键每个云函数文件夹 → **上传并部署：云端安装依赖（不上传 node_modules）**：

| 顺序 | 云函数名 | 主要职责 |
|------|----------|---------|
| 1 | `auth-login` | 用户登录（微信 openid + 密码） |
| 2 | `data-query` | 商品/客户/区域/订单/用户/赊销看板 查询 |
| 3 | `product-write` | 商品增改 |
| 4 | `customer-write` | 客户增改 |
| 5 | `order-write` | 订单创建/状态流转/**收款登记/确认收款**/备注/打印标记 |
| 6 | `region-write` | 区域增改 |
| 7 | `user-write` | 用户增改/分配角色/启用停用（微信原生，无密码） |
| 8 | `system-config` | 系统配置、SLA 定时任务、数据备份 |

**校验部署成功**：
- 云开发控制台 → 云函数 → 函数列表 → 状态均为「已部署」。
- 点任一个函数 → 版本 → 有 `$LATEST` 版本即为成功。
- （可选）点「云端测试」→ 输测试事件 `{"action":"ping"}`，返回 code=0 即可。

### 3.5 定时触发器（当前 MVP 无需配置）

> 📌 **当前 MVP（1.0）已取消双 SLA 超时自动**：分拣为一键「待分拣→已分拣」、出库为库管一步「待出库→已出库」，全部由人工操作，订单自动流转**不依赖**任何定时触发器，本节无需配置即可上线。

以下为**二期规划（当前未启用）**保留的定时触发器设计，仅当后续业务确实需要超时自动时才配置：

| 触发器 | Cron 表达式 | 逻辑（二期） |
|--------|------------|------|
| **14:00 分拣员超时自动确认发货** | `0 0 14 * * * *` | 当日 14:00 仍未确认发货的 submitted 订单 → 自动流转 checked（checked_by=系统自动，auto_checked=true） |
| **16:00 库管超时自动确认（配完）** | `0 0 16 * * * *` | 当日 16:00 仍未【配完】的 submitted/checked 订单 → 自动流转 confirmed（auto_confirmed=true） |

配置路径（二期启用时）：云开发控制台 → 云函数 → `system-config`（或独立定时函数）→ 触发器 → 新建定时触发器，填上表 Cron 表达式。

### 3.6 初始化账号（必须）

> 📌 微信原生身份：**首管理员零配置**——系统首次启动时不存在任何管理员，`login` 云函数在写入用户时检测到「当前无 admin」即把该 openid 自动设为 `role=admin`。即「第一个登录的人就是管理员」，老板部署后直接用微信打开小程序登录即可，无需配置任何环境变量、也无需先知道自己的 openid。后续管理员由首位管理员在「成员管理」里添加。

**方式一（默认·推荐）：首位登录者自动成为管理员（零配置）**

1. 部署上线后，老板用微信打开小程序 →「微信一键登录」。
2. `login` 云函数检测 `users` 集合中无 `role=admin` 记录时，自动创建并激活管理员账号（即老板本人）。
3. 登录后老板在「我的 → 成员管理」即可看到自己为管理员，并可继续添加其他成员 / 调整角色。
4. 若想在有人登录前就预置管理员（例如避免「谁先登谁就是管理员」），可用下方方式二/方式三预先建好 admin，则首位登录者保持其被分配的角色、不会再被强制升为 admin。

**方式二（可选）：环境变量预置首管理员 openid**

1. 云开发控制台 → 环境变量 → 新增 `ADMIN_OPENID` = 老板微信 openid。
2. `login` 云函数检测到该 openid 且 `users` 无对应 admin 时，自动创建并激活管理员账号。
3. **如何拿到「老板微信 openid」？** 三种方式任选其一：
   - ① **小程序端查看（最方便）**：老板用管理员身份登录 →「我的 → 我的 openid」点击即可复制（原型已内置该入口，部署后真实小程序同样提供）。
   - ② **云函数日志**：在 `login` 云函数里 `console.log(cloud.getWXContext().OPENID)`，老板首次微信登录后，到云开发「日志」中复制其 OPENID。
   - ③ **开发者工具**：微信开发者工具真机预览 / 编译，断点 `wx.cloud.callFunction` 返回结果里的 `OPENID` 字段。

**方式三：通过 `user-write` 云函数测试事件创建首管理员（无密码，仅写入身份与角色）**

1. 云开发控制台 → 云函数 → `user-write` → 云端测试。
2. 测试事件输入：
   ```json
   {
    "action": "create",
    "payload": {
      "name": "超级管理员",
      "role": "admin",
      "phone": "13800000000",
      "region": "HBQ",
      "status": "active"
    },
     "__skipAuth": true
   }
   ```
3. 返回 `code=0` 即为成功。

**后续初始化成员**（验收要求）：`admin` + 2 个 `orderer`（下单员）+ 1 个 `sorter`（分拣员）+ 1 个 `warehouse`（库管）。两种接入方式：
- **邀请制（主）**：管理员在「成员管理」填姓名/电话/区域 + 选角色 → 生成专属邀请二维码 → 员工微信扫码即绑定 openid 并激活。
- **自助审核（兜底）**：员工微信登录后进入「待分配」，管理员在成员管理列表手动选角色激活。

> 📌 微信原生无密码，无需设置/修改密码；账号安全由微信 openid 绑定保障。微信 App 内用户无法自行查看 openid，只能在小程序「我的 → 我的 openid」中由系统展示。

### 3.7 初始化业务数据（验收要求）

- **商品**：167 个（含 case/piece/unit 三种计价模式，件价/包价，单位统一「包」）。
- **客户**：120 个（11 个区域）。
- **订单**：28 笔，覆盖简化后状态机（待分拣 submitted / 已分拣 sorted / 已出库 confirmed / 已完成 completed），其中 2 笔 `auto_confirmed=true` 为系统自动出库演示；收款状态覆盖 未收(unpaid) / 部分收款(confirmed 部分) / 已结清(paid) / 待库管确认(pending) 各情形。
- **收款记录**：payments 至少 2 笔（pending 待确认 + confirmed 已确认 各 1，其中 1 笔含折价/货损 discount）。

## 4. 小程序端部署

### 4.1 代码中填入环境 ID

在全局初始化位置（`app.js`）把 `env` 改成 3.1 第 6 步的环境 ID：

wx.cloud.init({
  env: 'fenghuai-prod-xxxxx',   // ← 改成你的！

### 4.2 预览与真机调试

1. 开发者工具顶部 → "预览"：生成二维码，微信扫码打开真机调试。
2. 冒烟测试关键路径：
   - ✅ 微信授权登录（4 角色分别验证身份识别正确）
   - ✅ 首页快捷入口、今日统计卡正常
   - ✅ 录单：选客户 → 点「+ 添加商品」打开选品弹窗（默认 4 行常购商品、搜索后全列）→ 数量默认 0 → 件+包 → 提交
   - ✅ 分拣员确认发货 / 驳回（必填原因）
   - ✅ 库管配货 / 配完（录实际发货件数）
   - ✅ 赊销页：登记收款（下单员）→ 确认收款（库管）→ 客户欠款扣减
   - ✅ 订单列表当日分组卡片 + 历史折叠单行
   - ✅ 蓝牙打印送货单（含三方追溯 + 收款状态，无商户收款码）
   - ✅ 3 种 Excel 导出

### 4.3 提交审核与发布

1. 开发者工具顶部 → 「上传」。
2. 填版本号（示例：`v1.0.0`）+ 项目备注。
3. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 版本管理。
4. 刚上传的版本在「开发版本」中，点「提交审核」。
5. 填写审核信息：
   - 功能页面：首页、录单页、订单列表、分拣工作台、库管工作台、赊销页、我的
   - 测试账号：提供测试环境 openid 绑定为测试用户
6. 等待 1-3 工作日审核通过。
7. 审核通过后，版本管理页点「发布」→ **全量发布**。

## 5. 数据备份与恢复（最简版）

### 5.1 每日自动备份（免费额度足够）

1. 云开发控制台 → 云函数 → `system-config`（或新建独立 `db-backup` 函数）。
2. 逻辑：遍历 7 个集合 → 全部拉取 → JSON → 上传云存储路径 `backups/YYYYMMDD/集合名.json`。
3. 触发器：Cron 表达式 `0 0 2 * * * *`（每天凌晨 02:00 执行）。
4. 云存储 → 设置生命周期：`backups/` 前缀 31 天自动过期删除（防空间溢出）。

### 5.2 手动一键导出（临时备份）

云开发控制台 → 数据库 → 某集合 → 「更多 → 导出」→ 格式 JSON/CSV 立即下载。建议每周手动导出一次打包压缩存档。

### 5.3 恢复

云开发控制台 → 数据库 → 目标集合 → 「更多 → 导入」→ 选 JSON 文件 → 确认。

## 6. 监控与告警（极简）

### 6.1 云函数报错监控

云开发控制台 → 云函数 → 任一个函数 → 日志 → 错误日志。
- 巡检频次：管理员每周看 1 次即可。
- 错误率阈值：单函数日错误数 > 10 → 手动告警。

### 6.2 双 SLA 定时任务校验

每日核对：14:00/16:00 后，检查是否存在 `checked_by="系统自动"`、`confirmed_by="系统自动"` 的订单，确认触发器正常执行。

### 6.3 业务对账

通过小程序导出中心导出 Excel 与赊销看板核对（应收账款/实收/折价），无需额外监控系统。

### 6.4 联系技术支持（SLA）

- 严重故障（系统完全不可用）：微信联系项目负责人，**4 小时内响应**。
- 一般问题（小 bug / 界面优化）：**下一工作日 18:00 前处理完**。

## 7. 故障排查速查手册

### 7.1 小程序端

| 问题 | 可能原因 | 处理方法 |
|------|----------|----------|
| 打开小程序白屏 | 网络、AppID 错、代码包上传失败 | 重传代码包；检查 AppID |
| 登录失败：openid 未绑定 | 管理员没把该用户 wx_openid 绑定到 users 表 | 「用户管理」编辑 → 绑定 openid 或让用户首次登录绑定 |
| 商品/客户列表为空 | 集合权限设置过严 / 未初始化数据 | 检查 3.7 初始化数据与集合权限 |
| 提交订单失败：order_no 冲突 | 并发下单日单量超 9999 概率极低；偶发则重试 | 云函数内已做唯一性校验，一般不暴露 |
| 订单金额与预期不符 | 订单内自定义改价 / 客户上次价格 | 查订单详情 items_snapshot 实际存了啥 |

### 7.2 收款相关

| 问题 | 可能原因 | 处理方法 |
|------|----------|----------|
| 赊销页看不到某客户 | 该客户累计欠款为 0（默认隐藏） | 搜索该客户关键字查看 |
| 登记收款后状态没变 | 云函数 `order-write` 未部署 / 权限 | 检查云函数日志；确认操作角色为下单员/分拣员/管理员 |
| 确认收款按钮点不了 | 当前角色不是库管/管理员 | 收款确认仅限库管/管理员 |

### 7.3 蓝牙打印

| 问题 | 可能原因 | 处理方法 |
|------|----------|----------|
| 找不到打印机 | 手机蓝牙/定位权限未给；打印机没开机或没电 | 检查：设置 → 蓝牙开 → 定位开 → 小程序权限全部允许 |
| 打印机已配对但打印乱码 | 机型非 ESC/POS 指令集 | 买附录推荐机型（芯烨/佳博/汉印），均标准 ESC/POS |
| 打印一半中断 | 分包发送间隔过短；信号弱 | 代码中发送间隔调大（如 50ms→80ms）；重连再打 |

### 7.4 云函数 / 数据库

| 问题 | 可能原因 | 处理方法 |
|------|----------|----------|
| 云函数调用失败：-501000 无权限 | 云函数未部署；或小程序未绑定当前环境 | 云环境 ID 检查；重新上传函数 |
| 数据库查询超时 | orders/order_items 表大 + 缺索引 | 对照 3.2 检查所有索引，特别是 `(network_time, status)` 组合索引 |
| 双 SLA 没自动执行 | 定时触发器未配置 | 检查 3.5 触发器是否部署成功 |
| 云存储上传失败 | 容量超限；权限设置 | 云存储免费额度 5GB，清理历史备份；设置生命周期 |

## 8. 升级与回滚

### 8.1 小程序端版本升级

1. 修改代码 → 开发者工具「上传」新版本号。
2. 小程序后台 → 版本管理 → 提交审核 → 通过后发布。
3. 用户侧：微信自动更新（冷启动时更新），无需手动下载。

### 8.2 云函数升级

1. 改完本地云函数目录代码。
2. 开发者工具 → 云函数文件夹右键 → 「上传并部署：云端安装依赖」。
3. 新版本对新请求立即生效（Serverless 冷启动新实例），无需停服务。

### 8.3 数据库结构变更

1. 云开发控制台 → 数据库 → 集合 → 调整字段/索引。
2. 存量数据如缺字段：可用云函数遍历补写默认值（如 `payment_status=unpaid`、`usage=0`）。

### 8.4 回滚

| 模块 | 回滚方法 |
|------|----------|
| 小程序 | 小程序后台 → 版本管理 → 历史版本 → "回滚"（审核通过的版本都可一键回滚） |
| 云函数 | 云开发控制台 → 云函数 → 版本 → 选历史版本 → "设为 $LATEST" |
| 数据库 | 5.1 的 backups 目录 JSON → 云开发导入恢复 |
