## 经验列表

### E-001 同一文件并行 SearchReplace 写竞态，修改被静默覆盖

| 项 | 内容 |
|----|------|
| **日期** | 2026-08-03 |
| **现象** | 对同一文件**并行**提交多个 SearchReplace 编辑时，diff 全部显示"修改成功"，但实际只有部分修改生效，其余被后面的写入静默覆盖。多处修改丢失后才发现：如订单号前缀"FH-"改"丰淮商贸-"、商品默认数量0、排序代码等被还原为旧值。4个文档（PRD/ERD/API/TDD）和 UI 原型均出现此问题。 |
| **根本原因** | 同一文件的多个并行编辑基于同一旧版本计算 diff，后写入的覆盖先写入的（最后写入者胜），导致前面已成功的修改丢失；工具返回成功但内容未保留，具有欺骗性。 |
| **解决方案** | **对同一文件的多次编辑必须串行执行**（一次只发一个 SearchReplace，确认生效后再改下一处）；不同文件之间可以并行。修改完成后必须用 Grep/Read **复查关键字段是否真实落盘**，不能只信 diff 提示。 |
| **影响范围** | 所有文档/代码批量修改场景。检查清单：改完 grep 验证关键数字/字段名/枚举值在各处一致（与"改代码同步改文档"门禁结合执行）。 |

---

## 检查提醒（每次开发前默读）

1. 同一文件编辑 → **串行**，禁止并行
2. 修改后 → **grep 复查**，不信 diff 提示
3. 文档与代码 → **100% 同步**，关键字段 grep 一致
